# Learnings — Active Guidelines

Distilled from 40 past learnings (archived in `past_learnings.md`). These are principles to apply going forward.

---

## Current Critical Guardrails

- **AQL/Zopedia has one orchestration spine.** Chat, live research, homepage summary, page summary, evidence-pack generation, critique, and maintenance are modes of one engine contract. Do not add or extend feature-specific LLM/research endpoints when the work belongs in the shared AQL/Zopedia engine.
- **Memory/wiki/tool access is a product contract, not an optional helper.** Any research-grade AQL, Attention, Summary, SAA, or Zopedia surface should enter through the shared engine so it gets the same planning, tools, evidence pack, memory reads, critique, and write policy.
- **Before touching Zopedia/AQL/Attention/SAA LLM paths, read `documents/reference/AQL_ZOPEDIA_ENGINE_GUARDRAILS.md`.** The long numbered list is history; the reference file is the active operating rule for this failure zone.
- **Tool boundaries repair tool-contract failures before product answers.** If an LLM emits malformed but recoverable tool arguments, such as flattened Python or stringified dataset refs, normalize and run one bounded repair at the shared tool boundary. Do not let a code-generation error become a false "data unavailable" answer.
- **Analysis repair must be execution-proven, not just attempted.** A repaired Python string can still fail on indentation, missing columns, timezone joins, or hidden stdout. Give the repair pass actual input schemas/samples, allow safe pandas methods, normalize narrow generated-code formatting defects in the sandbox, and expose stdout/tables back to synthesis before calling the tool path fixed.

## Architecture

1. **One source of truth, one shared contract.** Shared behavior lives behind one execution core. Streamlit, REST, and MCP are thin facades. Datasets, charts, artifacts, and auth scopes are first-class objects — not UI text other clients parse.
2. **Fix at the source, not in the UI.** If a summary or dashboard is wrong, fix the upstream data or service path. Build rollups from the same payloads used by detail views so they cannot drift.
3. **Persist important product state as first-class data.** If something must appear in the product, it needs a dataset or event — not a narrative side effect. Usage telemetry comes from durable DB events, not container logs.
4. **Config-driven over hardcoded.** Mappings, thresholds, and graph definitions go in versioned config or data files. When deterministic and retrieval-backed logic both contribute, update one shared status contract.

## Operations

5. **Azure runtime is the source of truth.** Local generated files are fallback only. Normalize equivalent env vars to one setting. Standardize on one Key Vault.
6. **Image promotion and env promotion are separate.** A promoted image digest does not carry new env keys. Deploy scripts must manage both.
7. **Identity-driven jobs need deploy-time sync and runtime fallback.** Attach the managed identity on every update. Fall back to the default attached identity when the configured client id is stale.
8. **Scheduled jobs fail on missing mandatory inputs.** A green skip for a required dataset hides stale data and delays incident detection.

## Security

9. **Source-control discipline and fail-closed defaults.** Any secret in a tracked file is compromised. Notebooks and legacy folders are full scan scope. Auth paths fail closed when dependencies are unavailable.
10. **Token-signing keys have their own lifecycle.** Do not borrow user passwords for signing. Browser-readable cookies are a workaround, not a design.
11. **Telemetry before credentials.** Enable auditing and diagnostics before or alongside any rollout that introduces real credentials. Missing audit trails are security defects.

## Testing & Validation

12. **Smallest callable unit first, then the full user path.** Reproduce issues at the store/service level, then verify the exact runtime path the user hits — including materialized and cached paths.
13. **Raw SQL gets a direct store test.** Service tests are not enough when the bug is in a SQL string.
14. **Streamlit changes need render checks.** `AppTest` verifies block order and visible text. Seed `_ui_user_context` for admin pages. Check presence and absence.
15. **Azure CLI success does not prove app-runtime RBAC.** Verify at least once from inside the live container with the app's actual managed identity.

## Evidence & Retrieval (AQL / SAA)

16. **One shared evidence trace.** All research paths route into `search_results -> source_documents -> evidence_chunks -> claims`. No parallel corpora.
17. **Retain the richest text available.** Prefer page text > provider text > snippet. When a source is worth opening, its text budget must be large enough to matter.
18. **Storage, then access, then retrieval.** First: stable document ids and durable blobs. Second: a shared search and document-open contract. Third: chunk history. Fourth: hybrid retrieval. Do not skip steps.
19. **Chunks are the reasoning unit.** Persist chunk history at write time. Keep the searchable unit aligned with what the pipeline actually reasons over.
20. **Match signals separate from rerank signals.** Lexical and semantic overlap determine match. Authority and freshness determine rank order.
21. **Vendor bulk endpoints are optional.** Keep the stable per-series path available. One shared payload shape behind both strategies.

## Agent Quality

22. **Retrieval before choreography.** Fix retention and retrieval before adding multi-agent orchestration. Advanced patterns do not rescue weak evidence.
23. **Agent tools must match the product promise.** If the feature promises search-backed analysis, the tools must include the actual research sources. The model cannot use tools it cannot see.
24. **Internal evidence first, external search second.** The SAA retained evidence store is a high-value, low-latency source. Agent prompts should direct the planner to search retained evidence before calling live web search APIs. This avoids missing evidence the system already has and reduces latency.
25. **Preserve the user's query phrasing through the search pipeline.** Intent classification is useful for routing but strips domain-specific terms. The original query text must reach the search API to avoid losing key phrases like "short squeeze" that the classifier maps to generic categories.
24. **Gap detection over source count.** A system can browse and search broadly but still sound flat if it compresses evidence too early and never asks what is still missing.
25. **Different surfaces need different writers.** Homepage summaries, narrative cards, and audio need different density and evidence presentation. Do not reuse one compact format for all.
26. **Generic phrasing triggers another research pass**, or at minimum a clearer "unresolved" explanation. Accept `"no clear catalyst"` only when the system has actually searched and found nothing.
27. **Consolidation should preserve shims while moving ownership.** When retiring legacy Attention reasoning paths, first move the source function into AQL/compute/Attention-owned signal modules, then keep thin compatibility imports until pipeline jobs, presentation loaders, and tests are retargeted.
28. **Single-shot LLM summaries hallucinate specifics; ground them with a critique+judge layer.** When the synthesizer LLM only sees text beats (no numerics, no source claims), it will invent percent moves and contradict its own catalyst names. The fix is two extra personas after synthesis: a critique agent with a focused tool subset (price lookup, evidence search, recent news) that flags numeric/contradiction/unsupported issues, and a judge LLM that rewrites only the flagged passages. Both must be best-effort with fall-through to the original summary so the pipeline stays robust. Pattern lives in `services/aql/critique.py`, wired into `build_attention_agentic_summary_with_trace`.

## LLM Integration

27. **All user-facing narrative is LLM-generated.** No `f"Oil is {direction}"`. No if/elif dispatch for narrative variation. Structured data goes into the LLM prompt; natural language comes out.
28. **LLM readiness is verified at startup.** `check_llm_readiness()` logs provider, model, deployment, and embedding status. "Embedding client exists" does not mean "embedding deployment is provisioned."
29. **Research browsing degrades cleanly.** Use Playwright when available, fall back to HTTP extraction. Keep planner bias soft — encourage tools, do not force fake research loops.
30. **Gated-source auth fails fast.** Fetch the target page first, authenticate only when gated. A slow fallback is still a broken product path.

## UI & Product

31. **Actions before containers.** Start with what the user needs to do per row, then pick the UI component. Backend mutations before UI polish.
32. **No implementation details on user screens.** Architecture explanations go in docs. If the text does not change the next click, remove it.
33. **Every word the user reads must add information.** The token-to-information ratio is the most important UX metric for LLM-generated content. Internal quality signals (critique summaries, review assessments), raw tool/source names (Investigator.Company Context, Dataset.Recent News), and verbose "we found nothing" paragraphs are waste. If there's no catalyst, say "No catalyst identified" — not a 40-word paragraph explaining that the absence of evidence is accurately reflected. Confidence labels only appear when high. See `documents/architecture/UI/ENRICHMENT_PHILOSOPHY.md`.
33. **Loading states reuse real backend stages.** Surface the agent's actual reasoning and tool calls — do not invent a generic progress bar. Keep the trace visible after completion.
34. **Precompute expensive media in the job.** TTS and heavy enrichment run in the scheduled job and persist with the snapshot. On-demand fallback is recovery, not the primary path.
35. **Tabs evaluate all bodies.** For heavyweight admin screens, use `st.segmented_control` with conditional rendering instead of `st.tabs`.

## Caching

36. **Local cache is disposable.** Blob storage + manifests are the durable layer. Cache caps and pruning live in the shared cache helper.
37. **Derived summaries rebuild from raw data on read.** Treat stored summary tables as performance convenience, not independent authority. Check whether a broken derived field can be recomputed before debugging the UI.

## Macro Dashboards

38. **Three lenses: hard data, market pricing, transmission.** Inflation, labor, and housing activity alone are not enough. Add curve shape, real yields, breakevens, dollar, and bank-credit flow early.

## Documentation

39. **Move stable architecture out of task plans.** Durable design docs belong under `documents/architecture/` with a local README. Leave short-lived fixes and recovery notes in `documents/plans/`.
40. **Use plain domain terms.** Prefer "text", "narrative", "market activity", and "market overview". Avoid legacy market-media jargon in product/domain code and docs; technical dataframe duplication APIs are still fine.
41. **Knowledge graph is a prior, not evidence.** AQL can use the reviewed graph to find entities, paths, hypotheses, and graph change candidates, but final causal narrative still needs current evidence and claim support. Keep graph persistence owned by `services.knowledge_graph`; let AQL write through typed graph-service commit APIs with audit/rollback, using review escalation for risky changes, not ad hoc SQL or silent narrative-time mutation.
42. **Resolve graph subjects before graph search.** Do not pass full AQL narratives directly into KG node search. Extract symbols, aliases, and domain terms first; otherwise generic words like "company", "demand", "and", or "on" can create high-confidence false graph matches.
43. **Entity extraction must be independent and non-blocking by default.** Broad taxonomy and universe lookups can touch materialized storage. Keep shared entity extraction on feed metadata, KG aliases, claim entities, and optional LLM output unless a caller explicitly opts into heavier lookup. Do not make entity extraction an AQL-owned subsystem.
44. **Knowledge-graph exploration should be entity-first.** UI graph builders should extract and link entities before running graph search or expansion. Raw text search is useful fallback for short manual seeds, but linked entities make add/remove review safer and easier to audit.
45. **Large graphs need an overview before search.** Exploration pages should show a capped, ranked subgraph on first load. Empty screens make users guess what the graph contains; full graphs become unreadable.
46. **Disconnected graph components need their own layout space.** A single force-directed simulation can overlap independent subgraphs because no edges separate them. Lay out components independently, then pack them with padding before rendering.
47. **Graph visuals must show graph semantics.** If the stored model has directed edges, confidence, and severity, the visualization must encode those fields directly. Otherwise users are judging a simplified drawing, not the graph they are being asked to validate.
48. **Attention jobs should propose KG changes, not apply them.** Scheduled runs can extract entities and causal edges from fresh evidence, but core graph writes need review until proposal precision is measured. Materialize proposal rows first, then let the graph review UI commit approved deltas.
49. **Page summaries need one shared contract.** Market, stock, macro, and trading surfaces should pass structured page facts into one LLM-backed summary helper, then render the returned headline, watch items, gaps, and confidence. This keeps summaries consistent and lets downstream agents consume them without scraping UI text.
50. **Shared contracts still need shared evidence.** A common page-summary schema is not enough; agentic summary surfaces should reuse AQL / Zopedia for retained evidence, live evidence, ticker tools, and verification, then adapt that grounded output into the schema.
51. **Render paths stay cheap.** Main research features should render existing state first and make expensive AQL/LLM work explicit through a button or a scheduled job. Caching reduces repeated cost, but it does not make first-load agent runs acceptable.
52. **Batch labels from materialized snapshots.** Company names and display metadata should come from universe snapshots where possible. Per-symbol fallback is acceptable for a small selection, not for a full market table.
53. **Fixed market feeds materialize beside their summaries.** The Market Opportunity feed is derived from scheduled mover and momentum snapshots, so the attention job should persist the ranked feed and the UI should only select the requested focus/horizon from that materialized table.
54. **Materialized summary contexts must match UI contexts.** If a page summary is resolved by context signature, the job and UI must build the same compact context. Do not include job-only source row counts that the page no longer loads.
55. **Use compact guardrail references for repeated failure zones.** When mistakes/learnings get large, create a short reference file under `documents/reference/` that names the relevant IDs and the required architecture. Read that file before touching the same feature family again.
56. **Job-owned agentic work still needs bounded steps.** Scheduled materialization keeps page load fast, but it also needs per-step timeouts around external AQL/search/LLM paths, including downstream bundle writing and verification. Otherwise the job can hang before writing the cached outputs the UI depends on.
57. **Persisted job frames need explicit dtypes.** Review/proposal frames that mix optional text defaults with numeric values can fail only at parquet upload time. Coerce numeric review fields before handing frames to the pipeline store.
58. **Shared AQL in jobs is also a packaging contract.** If a scheduled job reuses AQL/Zopedia modules, the job image must copy the same dependency folders the UI/API image has, not only `services` and `pipeline`.
59. **Fallback contracts need end-to-end tests at the outer timeout layer.** It is not enough to test that the summary helper falls back when AQL raises. Also test that the scheduled job timeout wrapper writes the same `fallback` schema, because that is the row the UI actually reads.
60. **Ticker identity is not a metric.** In dense trading or research cards, render ticker plus company name as the row identity and use metrics only for numeric values. Narrow metric widgets clip symbols and hide the context needed to judge a setup.
61. **Trading signals need a visual audit trail.** A composite score should show its visible components, selected horizon, trend quality, and missing data. Otherwise users cannot tell whether the setup is driven by a real trend, a one-day move, or an unexplained internal rank.
62. **News-count summaries are metadata, not context.** Sentences like "6 recent articles over 4 days; tone is mixed" can explain coverage volume, but they should not fill Background or What Happened slots. User-facing context sections need substantive company or catalyst text, or a clear unavailable state.
63. **Slow company context belongs in its own dataset.** Company background changes slowly and can be prefetched monthly from universe/taxonomy/Wikipedia. Daily attention jobs should update catalysts and headlines, then merge the slow baseline only when the narrative text is missing or generic.
64. **Public reference APIs need polite batch defaults.** Even low-volume scheduled jobs should identify themselves and include a configurable inter-request delay. This keeps small tests and future larger runs from accidentally behaving like a scraper.
65. **Company names need source-aware cleanup.** Exchange/universe names often include share-class and legal suffix text that does not map to reference pages. Try the official display name first, then a cleaned legal-suffix candidate before falling back to generic company text.
66. **Prebuilt audio is tied to generated text.** Homepage audio length is controlled by the materialized `audio_text` from `attention-home-build`, not only the render-time display limit. Regenerate the job output after prompt changes, and store a text hash beside embedded TTS bytes so stale audio can be detected.
67. **Research agents should avoid execution-like market wording.** Prompts that say "trade candidates", "short/avoid", or "execution" can be rejected before the model sees the safety qualifiers. Use neutral watchlist and downside-risk language in LLM prompts, then map back to UI labels after generation.
68. **AQL sidecar calls need transient retries.** Interactive surfaces that call AQL tools inherit flaky web/search/source connections. Retry dropped connections once at the feature boundary and translate repeated transport failures into a human-readable data gap.
69. **Transport sanitization belongs at shared agent boundaries.** Fixing one feature wrapper is not enough when the same Zopedia agent powers multiple surfaces. The shared agent and UI shell should both translate dropped HTTP/model connections before raw provider exceptions reach the page.
70. **Reasoning-provider swaps need adapter seams.** Providers that expose reasoning traces may not share OpenAI/Azure strict JSON schema semantics. Add a provider adapter, capture the provider's reasoning field as trace metadata, and route it per agent before changing the app-wide LLM runtime.
71. **Runtime refresh triggers should use runtime credentials, not deployment tools.** Streamlit containers should not need Azure CLI to start a precompute job. Use managed identity plus Azure Resource Manager for in-app job triggers, with CLI only as a local developer fallback.
72. **Routers enrich chat requests; they do not decide whether the agent runs.** In chat-style research UI, deterministic routing should add direct matches and context metadata, then hand the request to the agent. Bare replies like "yes" also need to resolve against the prior assistant turn before enrichment so the agent receives an actionable continuation.
73. **Every model step in an interactive agent needs its own timeout.** Tool timeouts are not enough. A planner or final synthesis call can hang after useful evidence has already been collected, so bound each LLM step and degrade to synthesis or evidence-state fallback.
73. **Social state needs stable content anchors.** Reactions, comments, and share artifacts should attach to materialized run IDs, context signatures, tickers, bundle IDs, or content digests. Do not anchor durable interaction state to rendered markdown, card order, or `st.session_state`.
74. **Operational job controls belong in admin.** Feature pages should read materialized datasets and expose product actions only. Job starts, retries, and refresh controls live in Admin > Pipeline Jobs.
75. **Log-only trade actions should keep execution fields.** Even before Alpaca order placement is enabled, persist execution mode, broker, broker order id, and intended order payload so the future broker transition is an extension of the audit record.
76. **Required agentic horizons need auditable output, not silent absence.** Original lesson: if AQL times out in a scheduled Trading Agent build, use the materialized opportunity feed to persist conservative low-confidence candidates and record the AQL gap. v0.6 supersedes the candidate part: every horizon still needs a persisted run state, but research candidates should only be created from gateway-governed AQL/Zopedia evidence.
77. **Interactive agents need deterministic evidence seeding.** For common query shapes, collect the obvious first evidence before asking an LLM planner: ticker context for ticker questions, all ticker contexts before comparisons, live event evidence for current catalyst questions, and the materialized homepage summary for broad "what matters" prompts. The planner should refine evidence, not spend latency discovering the first step.
78. **Generic tool summaries can hide the real answer.** Rich dataset payloads like `attention_home_1d` need a purpose-built LLM context extractor. Passing only object keys and run IDs makes the synthesizer claim missing current data even when the materialized narrative is present.
79. **Planning and synthesis can use different model latency profiles.** A reasoning model can be useful for tool choice and trace capture, but final synthesis after deterministic evidence seeding is mostly compression. Keep a scoped synthesis-model override so Zopedia can reduce latency without changing the app-wide LLM runtime.
80. **Interactive agent tools and hidden preparation steps need heartbeats and timeouts.** A visible planner heartbeat is not enough if the current step is inside a slow live-search tool or a prefetch keyword extractor. Bound each nontrivial external/LLM step, emit elapsed-time progress, and synthesize from collected evidence when a step times out.
81. **Auth-action URLs are separate from app routing.** Reset and invite tokens should force a logged-out auth screen, skip public-home shortcuts, and never restore cookies before the form is shown. Completing a reset should not create a session; users must authenticate with the new password.
82. **Session validity is dynamic.** Restoring a browser/API session must re-check `users.status`, active portfolio status, and active membership. Authenticated context is not just a non-expired session row.
83. **Zopedia parity starts headless.** Before renaming or polishing UI, prove the memory loop as source text -> SAA retained document -> chunks -> wiki pages -> graph links -> automatic guarded mutation. Transcript text already fits the SAA retention/search layer, but native ingest, durable wiki pages, source tracing, audit, rollback, and review escalation are the real integration gates.
84. **AQL must be the research-grade LLM boundary before Zopedia.** Adding wiki memory only improves every surface if attention summaries, page summaries, Trading Agent, stock pages, and chat all consume the same AQL evidence pack. Direct LLM calls can stay for metadata/routing/formatting, but not for independent market narratives.
85. **Fail closed instead of inventing fallback narrative.** If AQL or the formatter LLM cannot produce a grounded page summary, return an unavailable state from the scheduled summary artifact. Do not turn structured rows into hardcoded summary prose or ask the user to repair the missing artifact from the feature page.
86. **Feature pages consume generated research; Admin operates jobs.** Product screens should show current answers, evidence, progress, and quiet unavailable states. Manual analysis buttons, FRED load controls, materialized/scheduled/precomputed language, and run-job controls belong in Admin/docs/logs, not in Broad Economy, Market Explorer, or Stock Investigator.
87. **Zopedia memory is SAA-owned wiki state.** Native Zopedia should persist source-backed pages, links, source URLs, mutation logs, and escalated proposals in SAA tables, then expose them as agent tools. AQL can read and cite those pages, and safe writes should go through explicit typed commit APIs with audit/rollback.
88. **YouTube transcript support needs provider diagnostics.** Even with a transcript library and timedtext fallback, YouTube can IP-block server environments. Return a clear unavailable status and allow pasted transcripts/source text so Zopedia ingestion still works.
89. **Macro graph thresholds must preserve obvious shared-role clusters.** Rates ETFs sharing sector, rates role, and macro tags should clear the graph edge threshold. If graph policy changes, test obvious rates/oil/defensive clusters end to end, not only individual candidate scoring.
90. **Auth-action cleanup has two phases.** Opening a reset/invite link must clear existing sessions before rendering the form; any later successful login must also remove the auth-action query params so refreshes and new tabs restore the new session normally.
91. **Browser persistence needs a completed render.** A cookie-setting component is not durable until the frontend mounts it. After login, update session state, render the cookie sync, and continue into the authenticated app instead of forcing an immediate rerun.
91. **Model access needs one named product boundary.** Feature code and jobs should not call the raw LLM loader directly. Route model access through a shared Zopedia/AQL boundary that requires a named surface, then scan for violations in tests so new orphan model calls fail fast.
92. **Zopedia quality needs answer-level evals, not only tool checks.** A tool trace can show `zopedia.search_pages` while the answer still says no memory was found. Product evals must inspect the final answer for memory use, page reads, citations, limitations, and contradiction with the tool state.
93. **Long natural-language memory search needs a tolerant fallback.** SQL full-text filters can miss useful pages before the app-level scorer gets a chance to rank them. For Zopedia wiki search, use strict full-text first, then fall back to a bounded candidate set and lexical scoring when the strict query returns nothing.
94. **Memory search should usually be followed by page read.** A Zopedia search result gives a map; the answer should read the page before treating memory as evidence. The planner contract and evals should check that memory-backed answers actually read and cite pages.
95. **Evidence contracts are not query keyword routers.** Zopedia can require grounded behavior — company questions need fundamentals/news/history, macro questions need local data first, stale memory needs guarded mutation, false premises need verification — without hardcoded query word lists. Put the standard in the planner contract and eval gates, not in code branches that pretend to classify the user's intent.
96. **Hard questions need evidence coverage, not only tool traces.** A trace that shows one plausible tool can still produce an overconfident answer for a multi-part question. Track required evidence slots, filled slots, missing slots, and answer confidence before final synthesis.
97. **Zopedia parity is a runtime and maintenance contract, not just wiki storage.** Source immutability, page schemas, backlinks, godnodes, compaction, merge, tool budgets, two-phase tool resolution, source tracing, automatic guarded mutations, and answer-level evals all have to exist before calling the feature complete.
98. **Zopedia UI should lead with reasoning trace and source ingestion, not graph decoration.** Streaming tool/reasoning progress, custom uploads, source tracing, page inspection, mutation audit, rollback, and review escalation are core. Full graph exploration should wait until provenance, backlinks, and godnodes make the graph semantically meaningful.
99. **Zopedia should auto-improve memory when evidence is strong enough.** Review queues are still needed for risky, ambiguous, destructive, or low-confidence changes, but the target product is an autonomous memory loop. Safe source-backed page creation, source attachment, link addition, aliasing, contradiction annotation, and timestamped fact updates should commit through typed APIs with audit and rollback metadata.
100. **Zopedia maintenance is core product behavior.** A durable wiki memory system degrades without compaction, duplicate detection, link repair, staleness checks, contradiction handling, source-coverage checks, and maintenance reports. Treat maintenance as part of the engine, not an advanced UI follow-up.
101. **Provider reasoning belongs in the shared LLM adapter.** DeepSeek `reasoning_content` should be captured once in `services.llm.DeepSeekChatJSONClient` and carried through the shared response contract. Do not create Zopedia-only provider overrides when the intended change is the global LLM layer.
102. **Wiki source refs need a read-through tool.** A page-level source list is not enough for grounded answers. Agents need a stable `read_source` operation that can open Zopedia source pages, retained SAA chunks, retained source documents, and URL refs from the same source-ref contract.
103. **Deploy scripts must preserve explicit runtime overrides after sourcing generated env files.** `VAR=value deploy_script.sh` is not reliable if the script sources `infra/.generated/deployment.local.env` afterward and treats sourced values as overrides. Capture requested env first, restore after source, and clean provider-specific stale env during deployment.
104. **Scheduled job env needs last-wins normalization.** Common runtime env belongs on every job, but per-job overrides must replace common entries before calling Azure. De-duplicating by env name keeps one deploy path while still allowing special timeouts or job-specific knobs.
105. **Upload ingestion belongs behind the memory service contract.** The UI should only collect the file. Decoding text/PDF bytes, rejecting unreadable binary, preserving filename/content metadata, and passing provenance into generated pages belong in Zopedia/SAA services so API and agent paths can reuse the same behavior.
106. **Answer critique belongs at the shared agent boundary.** A judge pass should review the draft against the exact tool evidence before the answer leaves Zopedia, then revise or lower confidence through the same result contract. Putting this in page-specific UI code would miss API, chat, and future agent surfaces.
107. **Automatic memory writes need a ledger at the write boundary.** Source-backed Zopedia ingest should commit page rows and mutation audit rows in the same service transaction, then expose the audit through agent tools. A separate review/proposal table is not enough for autonomous memory improvement.
108. **Rollback should execute from stored snapshots, not fresh inference.** If an audited Zopedia mutation has before/after page snapshots, undo should restore those rows and archive newly created rows directly. Do not ask an LLM to reconstruct prior state.
109. **Zopedia maintenance belongs in jobs, not chat.** Chat should read maintenance reports and mutations. Backlink rebuilds, community/godnode indexing, stale/orphan/source checks, and memory-health reports should run as scheduled jobs and write durable SAA rows.
110. **Typed memory mutation is the source of truth.** Safe automatic Zopedia writes should enter through one service function that creates before/after state, evidence refs, audit rows, and rollback handles. Agents and UI should not patch page rows directly.
111. **Risky memory edits should still use the same contract.** Delete, merge, rewrite, source removal, and low-evidence changes should become proposals through the typed mutation API until the executor has measured precision and judge coverage.
112. **Feature pages read memory health; admin owns operations.** Showing latest Zopedia health, communities, issues, and rollback actions is product behavior. Triggering or retrying scheduled maintenance remains an admin/pipeline concern.
113. **Dev job deploys need a runnable proof.** Creating a scheduled Container Apps job is not enough for engine work. Start one dev execution, verify completion, and record the counts before calling the job wired.
114. **Zopedia UI should hide engine plumbing by default.** Proposals, mutations, and health are still core engine state, but they should be automatic and agent-readable. The main product surface should be chat history, upload, trace, citations, and a compact health signal.
115. **Streamlit mobile checks need Streamlit-specific state assertions.** Selectbox selected values can live in the combobox `aria-label`, not text content, and Streamlit may scroll `stAppScrollToBottomContainer` instead of the document. Browser checks should assert the selected value and reset Streamlit scroll containers before screenshots.
116. **Agent-run analysis needs a sandbox, not shell access.** For EDA and scikit-learn, let the agent choose datasets and generate code, but execute only in a bounded runner with approved dataframe inputs, no network/secrets/shell, stored artifacts, and source refs.
117. **Agent analysis inputs should enter through QueryService.** Letting generated code fetch data recreates orphan data paths and secret/network risk. The agent should name approved datasets and params, then the runner receives already-materialized dataframes plus provenance.
118. **Shared data dependencies need major-version caps across containers.** The UI/API Python 3.10 images and pipeline Python 3.11 images can resolve different latest wheels. Pin pandas below the next major release until the whole stack is tested against that major version.
119. **Chat history is product state, not an agent run log.** The run log is for audit/debug. A conversational product needs thread and message tables that can replay assistant payloads, traces, citations, memory updates, and confidence.
120. **Automatic memory needs a post-answer maintainer.** Planner-time tools can update memory when the user asks directly, but normal answers need a bounded post-answer pass that reviews final evidence and routes safe writes through typed mutations or risky writes through proposals.
121. **Synthetic sources are not citations.** Eval/debug pages can live in the same wiki tables, but normal search and answer citation strips should filter them through source metadata and URL validity. A fake URL like `eval.local` is useful for test provenance, not for user-facing evidence cards.
122. **Zopedia controls need product tabs, not stacked expanders.** History, source attach, and admin/debug are different jobs. Separate tabs make the chat surface cleaner and keep engine state inspectable without making it look like the main workflow.
123. **Answer text is an interaction surface.** Zopedia answers should be sectioned Markdown, then rendered as selectable passages. A selected passage can become the next scoped query, which is cleaner than adding more global buttons around a dense answer blob.
124. **Browser-path validation beats implementation inspection for agent UX.** A Zopedia change can pass unit tests while the live page still exposes tool names, unrelated cards, or unreadable answer controls. Run the rendered chat path before calling the experience acceptable.
125. **Confidence is a coverage contract.** The judge can sound confident, but the shared agent boundary should still cap displayed confidence when evidence coverage is thin.
126. **Responsive helpers should be the only column boundary.** In Streamlit, broad mobile CSS can rescue many layouts, but routing every column through one responsive helper makes mobile stacking, desktop parity, and future page audits much simpler.
127. **Mobile first viewport should answer before it visualizes.** Dense graph or chart surfaces can be useful, but on phone screens the narrative or primary action should come first and the visualization should be optional or below the summary.
128. **Feature flags are deployment state.** A mobile implementation is not actually live until the Container App env carries the mobile flag and layout default. Deployment scripts should preserve those env vars the same way they preserve LLM/runtime config.
129. **Trace expansion is part of the trace contract.** If Zopedia advertises live reasoning/tool progress, the UI must keep that panel open during live updates and carry the same open state into the saved chat message. Treat open/closed state as product state, not widget decoration.
130. **Zopedia should feel like a research conversation, not a control panel.** History, source attach, admin, memory health, citations, and trace are supporting structures. The default visual hierarchy should be active thread, answer, evidence, composer; everything else belongs in rails, drawers, chips, or contextual actions.
131. **A high-bar plan needs a single execution spine.** Keep current status, blocker, roadmap, gates, and immediate next step aligned. If a plan says a feature is both "chat-first" and "not shippable," fix the plan before implementing.
132. **Separate implemented capability from proven product quality.** For Zopedia, judge/memory/mutation/maintenance code exists, but the remaining bar is measured behavior: hard-question evals, false-premise resistance, source coverage, safe automatic updates, rollback proof, and dev browser-path validation.
133. **Anti-fragility starts with guided-correction capture.** When a user shows the agent that a tool path exists, the system should mine the thread, identify the failed assumption, create a regression eval, update tool-affordance memory or planner contracts, and verify the next run reaches the answer without the same rescue.
134. **Good agent answers need evidence-slot planning, not just more tools.** The bond-yield dry run worked because it filled macro move, representative instruments, observed returns, statistical context, and causality caveats. The system should teach agents to plan/fill evidence slots and fall back across tool levels before saying data is unavailable.
135. **Self-improvement needs a ledger and promotion gates.** For Zopedia, "learn from mistakes" means persisted learning events, structured critic output, regression evals, safe tool-affordance or planner updates, replay verification, and regression monitoring. Without those gates, self-improvement becomes prompt drift.
136. **Empty rows need cause labels.** In the bond-yield thread, ETF `daily_movers` was empty because materialized movers excluded ETFs, event significance was empty because the post-event window had too few observations, and analysis was rejected because code/input contracts failed. Agents should surface the precise empty-result cause and try primitive fallback data before saying data is unavailable.
137. **Agent learning plans must include source-level tool fixes.** If a failure comes from ambiguous tool contracts, fixing only prompts or planner behavior is too shallow. The plan should require structured empty-result metadata, fallbacks in the tool layer, and evals that prove the agent no longer treats tool gaps as data gaps.
138. **High-bar plans need product proof and promotion rules.** Backend phases are not enough for Zopedia quality. The plan needs rendered UX gates, named golden scenarios, learning-update promotion rules, rollback requirements, and dev runtime proof before a feature can be considered excellent.
139. **Small tool previews can erase the evidence the model needs.** A daily-movers basket with five instruments is not useful if the LLM context samples only three rows and hides the missing proxy. Keep small evidence baskets visible in full.
140. **Partial materialized matches still need fallback.** If a materialized snapshot returns some requested symbols but drops the important ones, retry the primitive/on-demand path before letting the agent infer that the missing symbols have no data.
141. **Self-improvement needs an executable service, not only a plan.** A rescued chat should flow through one learning service that detects the failure, persists a ledger row, generates an eval, applies safe reversible memory updates, and exposes a job summary.
142. **Generated evals need literal failure strings.** High-level rules like "do not claim data is unavailable" are useful for humans, but regression tests need concrete forbidden answer patterns such as `stock data is unavailable`, `tool_call_id`, or `run_id`.
143. **Learning jobs need runtime proof, not only local proof.** After wiring an anti-fragile service, verify the deployed job image, provider env, one manual execution, and job counts. A local DB dry run is useful but does not prove the scheduled engine is live.
144. **Learning events need promotion states.** Detecting a failure, generating an eval, and applying a safe update are not the same as proving improvement. Replay the eval and mark events `verified` or `regressed` so the system can distinguish durable learning from hopeful mutation.
145. **AQL/Zopedia needs one orchestration spine.** Chat, live research, homepage summary, page summary, evidence-pack generation, critique, and maintenance should be modes of one engine contract, not separate endpoints with shared helper imports. Surface wrappers can differ, but planning, tool access, evidence capture, memory reads, and write policy must be centralized.
146. **Analysis repair needs input profiles and proof.** The latest Zopedia bond-yield thread showed the repair pass firing but returning code that still failed on indentation and dtype assumptions. Repair prompts should include actual frame columns/dtypes/samples, and the sandbox should normalize generic formatting defects and surface stdout/tables so a repaired run is useful to the final answer.
147. **Live news tools need internal budgets, not only outer tool timeouts.** The oil/geopolitics thread showed `research.live_event_evidence` timing out because it chained helper LLMs, SerpApi, Tavily, and symbol news under one 25s wrapper. Interactive news tools should use direct-query fallbacks, bounded helper calls, short provider timeouts, partial results, and contextual follow-up resolution so the agent can answer with whatever evidence arrived.
148. **Tool serialization and previews are part of the data contract.** The long-term trend thread showed `momentum_profiles` failing because an array-valued sparkline crashed JSON conversion, then `price_history` worked but the model treated a tiny sample as the full window. Data tools should serialize array-like cells safely and provide LLM-facing first/latest/return summaries for time series, not only row samples.
149. **Tool context should be summary-first.** Raw stdout, stderr, traceback, and logs are useful for debugging but expensive and noisy inside planner/final prompts. Normal tool results should expose counts, hashes, shapes, metrics, and artifact summaries; exact logs should require an explicit raw-output tool call.
150. **Visible planner/status prose is product content.** Zopedia's reasoning/status trace should remain visible when useful, but it must be rendered as a polished research narrative: readable step titles, compact arguments, paragraphs, preserved tables, and stable expansion. Do not treat visibility itself as the bug.
151. **Old endpoint names should be removed, not tolerated.** If AQL/Zopedia is the product spine, jobs, scripts, evals, and UI should call `run_aql_zopedia_agent`; the old Omnibar agent loop can remain only as a private implementation detail behind the engine boundary.
152. **Mobile auto-detection needs a normal-URL proof.** Streamlit server-side request headers may not expose the browser user-agent reliably enough for layout routing. For mobile web rollouts, verify the plain deployed URL on an iPhone-sized browser, then verify explicit desktop override separately.
153. **Mobile rollout defaults must preserve desktop.** Dev is the validation target for mobile web, but `STREAMLIT_LAYOUT_MODE_DEFAULT=mobile` forces desktop browsers into the phone shell. Use `STREAMLIT_LAYOUT_MODE_DEFAULT=auto` with a client-side phone redirect, then verify both a desktop viewport and an iPhone viewport against the plain deployed URL.
154. **Broad Economy summaries belong to the macro job.** The Broad Economy Zopedia Summary should be generated when FRED macro data refreshes, not as a side effect of homepage attention shortlist generation. Exact context matches are useful, but the page should fall back to the latest valid Broad Economy summary instead of showing a manual analysis button when formatting or lookback context drifts.
155. **Partial dataset writers need surface-aware reads.** If multiple jobs write different rows to the same materialized dataset, the reader must find the latest valid row for the requested surface instead of assuming the newest dataset version is complete.
156. **New page versions must carry forward every rendering concern.** When building v3 of a page (homepage, dashboard, etc.), audit the v2 renderer for every feature it renders — audio players, share buttons, debug traces, replay controls — and explicitly include or consciously drop each one. A feature matrix checklist before shipping prevents "where did X go?" moments.
157. **Token-to-information ratio is a first-class UX metric.** Every rendered word must help the user make a decision. Critique summaries, raw source/tool names, verbose "no data" explanations, and low-confidence labels are internal plumbing — they belong behind an admin debug toggle, not in the user view. The test: "If I removed this element, would the user lose decision-making ability?"
158. **LLM prompt tightness drives output quality more than post-processing.** Fixing verbose summaries at the prompt level (word caps, skip-empty-section instructions, structured section templates) is more effective and durable than trying to trim output in the UI. Post-processing is a bandaid; the prompt is the fix.
159. **Degraded states still need product hierarchy.** If cached or materialized product content is available, show it before setup/debug instructions. Runtime setup details such as Key Vault env vars, secret names, and shell commands belong in Workspace Status, Admin, logs, or docs — not above the user's market narrative.
160. **Completed agent traces should be answer-first.** Live Zopedia progress can stay expanded while work is running, but completed answers should land on the answer, citations, and compact trace summary. Raw model reasoning and memory-action deliberation should be available on demand, not the default viewport.
161. **A rendered summary and its narration must share one payload.** If Home renders a Zopedia market summary, its audio should be generated from that same Zopedia answer row. Keeping the older homepage summary audio beside a newer displayed answer creates a product-level mismatch even when both systems are individually working.
162. **Custom-domain health needs DNS-path checks.** Azure Container Apps can show a healthy revision and a valid custom-domain binding while the apex domain still resolves somewhere else. Verify apex and `www` DNS, `/_stcore/health`, and a real browser WebSocket session before calling the public site healthy.
163. **Streamlit request headers are mapping-like, not always dicts.** `st.context.headers` is a `StreamlitHeaders` object in current Streamlit, so helper code must accept `.items()` mappings. Dict-only checks silently drop user-agent data and can break server-side layout routing, audit logging, and auth metadata.
164. **Mobile/auth chrome should be copy-minimal.** Phone screens and login gates do not need generic captions like "secure access" or "private client workspace access." Keep authentication UI to the brand, required fields, actions, and explicit error/recovery states.
165. **Codebase efficiency means fewer owners and fewer paths.** When reviewing cleanup plans, focus on duplicated modules, stale wrappers, fallback branches, import direction, renderer ownership, tests that protect old names, and net production-line reduction. Do not translate "efficiency" into runtime token budgets when the task is codebase simplification.
166. **Second-pass cleanup must scan public surfaces and persisted labels.** After the main implementation path is renamed, check API routes, auth scopes, evidence-pack defaults, retained-memory provider strings, tests, docs, and UI references. These surfaces can keep old architecture alive even when the core function call has moved.
167. **Trading Agent analysis should start with the business, not the chart.** Price moves, technicals, and statistical anomalies are downstream artifacts of an operating company and its environment. For company watchlist candidates, the agent should first fill evidence slots for products, customers, demand, bookings/revenue quality, workforce/headcount, hiring, employee sentiment, web attention, global trends, and political/regulatory support before discussing price behavior.
168. **Zopedia news resolution should compare new facts to durable company memory.** A news headline should become a source-backed event, then resolve against wiki pages for the company, products, customers, fundamentals, workforce, risks, themes, and prior claims. The output should state what the news confirms, changes, contradicts, or leaves unresolved, with typed memory proposals when the durable story needs updating.
169. **Local DB-backed tools must read generated deployment context before declaring storage absent.** The UI/API scripts source `infra/.generated/deployment.local.env`, but Python service helpers may be called directly in notebooks, tests, or Codex probes. Secret resolution should use that generated Key Vault context and expose precise failure reasons; otherwise Zopedia, chat logs, auth, and retained evidence can look empty when only the local process env is incomplete.
170. **Admin observability should report dependencies, not only jobs.** Silent failures often happen below the scheduled job row: missing DB context, connector quota failures, provider timeouts, stale datasets, or retained error rows. The admin health surface should show job state, dataset freshness, connector call success/failure counts, and retained provider-error evidence in one place.
171. **A pytest hang needs a stack dump before a code fix.** Re-running only the blocked test with `faulthandler.dump_traceback_later` showed the exact provider call path: attention-home Zopedia market summary → ElevenLabs narration → `requests.post`. That made the fix a test-isolation change instead of a speculative timeout tweak.
172. **Optional DB helpers need bounded connection attempts.** A second stack dump showed market-opportunity focus lookup stuck inside `entity_taxonomy._db_connection()`. Graceful degradation only works if the connection attempt itself has a short shared timeout.
173. **Test fixtures should inject optional providers explicitly.** AQL search clients, Zopedia database connections, narration, and evidence-pass agents should be passed or patched at the test boundary. Global runtime discovery is useful in production, but it makes unit tests environment-dependent and can turn clean assertions into live provider calls.
174. **Cold-start memory needs a materialized draft layer.** When the committed wiki is thin, the first safe loop is to materialize source-backed draft business pages and resolution rows, then let future runs read those drafts before proposing or committing durable Zopedia mutations. This gives the system memory continuity without auto-rewriting company pages too early.
175. **Wiki context and company memory need different trust levels.** Zopedia theme/concept pages can explain the environment around a company, but they are not automatically facts about the company's business model. Generated company-memory drafts should only carry forward direct source-backed facts, otherwise one bad draft can recursively contaminate future memory.
176. **Materialized replay needs array-aware parsers.** Live pipeline frames may hold Python lists while persisted Parquet reloads them as NumPy arrays. Business-resolution and agent tools should normalize array-like cells before filtering symbols, entity refs, or source ids.
177. **Business-first news needs a ticker stack artifact, not just event memory.** A news resolver can compare one headline to prior pages, but the durable product contract should be `ticker -> business model stack -> event resolution`. The stack row makes products, customers, demand, fundamentals, workforce, web attention, policy, risks, and gaps reusable by attention, summaries, chat, and future jobs.
178. **A business stack needs an evidence plan, not only a schema.** A slot table without search/source requests still optimizes for completion. For business-first research, materialize the questions, query plan, connector requests, results, coverage state, and synthesis warnings so gaps are operationally actionable before the narrative layer writes a story.
179. **Business memory promotion needs two gates.** A search hit must match the company and the requested business slot before becoming a wiki fact. Generic pages returned by a slot query, such as stock quote pages or generic traffic-tool pages, should remain searchable evidence with coverage status, not durable company memory.
180. **Excellent answers make a call without padding.** When evidence supports a thesis, lead with it directly. When evidence is missing, name the exact missing source or business slot. Do not hedge by default, do not write process-heavy paragraphs, and do not turn retrieved snippets into a wall of text.
181. **Simplicity means fixing the contract at source.** The right simple fix is usually a better typed artifact, retrieval gate, source contract, or resolver boundary. Avoid extra sidecars, wrapper layers, and clever fallback choreography unless they remove real system complexity.
182. **Evidence labels must resolve into business verdicts.** "Quarterly results evidence exists" and "Glassdoor sentiment evidence" are not analysis. The contract must answer whether results are good, bad, or mixed, and whether employees appear happy, strained, or unknown from the evidence.
183. **Guardrails should remove unsafe paths.** A phrase blacklist catches symptoms after the product already went wrong. The durable fix is a stricter contract or state transition: if the verdict layer has not run, withhold the story and keep source facts internal.
184. **Business verdict synthesis belongs inside the AQL/Zopedia agent.** Ticker business stacks and news-business resolution should ask the shared tool-using Zopedia agent for structured verdicts. Feature modules can materialize facts, gaps, and rows, but they must not bypass Zopedia with direct `generate_json` synthesis paths.
185. **Local LLM config and secret lookup must share one env source.** Local commands can read Key Vault secret names from `infra/.generated/deployment.local.env`. Provider/model/base-url fields must come from the same source, otherwise a DeepSeek secret can be sent to the default OpenAI endpoint.
186. **Agent probes that use analysis subprocesses need real entrypoints.** Running AQL/Zopedia from `python - <<EOF` can break Python multiprocessing because child processes cannot re-import `<stdin>`. Use a script/module entrypoint for live probes and evals.
187. **Ticker cold-start should be robust to weak seeds.** If `company_baselines` is empty, use `us_equity_listings` when available, but ticker-only is still a valid starting clue. Let Zopedia/AQL recover the company, aliases, platform, peers, and business context during the general research thread; do not block research on a prefilled name.
188. **Business memory needs page text, not just search-result titles.** Serp snippets can locate official/company/SEC pages, but business facts should be extracted from opened page text where possible. The promotion layer must strip navigation, cookie, bot, and browser-warning boilerplate before facts enter the wiki draft.
189. **Generated deployment env must not override explicit unit-test env.** Local probes should read generated provider config when the process env is empty, but tests and shells that explicitly set `LLM_PROVIDER`/model/base-url need one coherent process-env config. Do not mix a process Azure provider with a generated DeepSeek base URL or temperature.
190. **Crawler escalation belongs in the shared page-acquisition contract.** If SERP/Tavily previews are too shallow, Zopedia/AQL should open the source through the shared browser path and escalate from Playwright/HTTP to Scrapling/Firecrawl when pages are blocked or shallow. Do not add feature-local scrapers; promote only source text that passes the business-slot and boilerplate gates.
191. **Blocked-page signatures must not be broad company terms.** Words like Cloudflare can be a company/business fact, not evidence of a bot wall. Use precise blocked-page phrases such as challenge text, Ray ID language, CAPTCHA, or verify-human prompts, and regression-test legitimate company pages that contain the same vendor names.
192. **Structured AQL repair belongs at the engine boundary.** If the shared Zopedia tool agent completes with a substantive markdown answer but misses the requested JSON envelope, the AQL/Zopedia engine should repair structure using only the agent answer. Feature modules should not add direct LLM fallbacks or silently degrade to `synthesis_unavailable`.
193. **Small-company retrieval needs exact identity plus distinctive-token matching.** For tickers that are common words or finance terms, do not let ticker-only or generic company tokens promote facts. Use exact company phrases first, then only distinctive short tokens such as `aehr`; generic terms like `capital`, `main`, `street`, `systems`, or `technology` should not stand alone.
194. **SEC and press-release boilerplate can look like business evidence.** Annual-report certification text and press-release headers can contain slot keywords without explaining the operating company. Treat them as source-location noise, strip datelines/headers, and promote only the sentence that says what the company sells, who buys it, what demand exists, or what changed.
195. **LLM qualitative features need live review, not fixed-string success.** Unit tests can protect schemas, source retention, and fail-closed state, but they cannot prove an LLM business story is good. Run the live path, read the verdicts, inspect gaps, and reject output that is thin, label-like, contradictory, or not in the spirit of the task.
196. **Business evidence should be prefetched before LLM verdicts.** If the stack relies on the agent to discover all evidence live, tool budgets can time out and the story becomes thin. Connector/crawler acquisition should materialize candidate evidence first, then AQL/Zopedia should judge what it means.
197. **Background research needs background budgets at the shared agent boundary.** Ticker business research is not an interactive chat turn. Give the scheduled AQL/Zopedia path long tool, prefetch, LLM-step, and candidate-research budgets through the engine boundary, while leaving interactive defaults short.
198. **LLM narrative paths must fail closed, not downgrade to deterministic prose.** It is acceptable for code to build IDs, counts, source traces, empty shells, and routing metadata. It is not acceptable for code to synthesize claims, causes, market stories, or verification verdicts when the LLM/Zopedia path is missing or failed. Empty narrative plus exact status is better than a fluent pseudo-story.
199. **Catalyst resolution is a reasoning job, not display copy.** The agent should identify the trigger or business development as deeply as possible, but the homepage should not keep printing "catalyst" as a section label or absence phrase. Render "what changed", the business context, and the exact evidence gap instead.
200. **Business-stack query planning still belongs to the general AQL/Zopedia agent.** If the full agent wanders or fails to emit the structured plan, fix the shared prompt, task/surface context, JSON repair, and trajectory monitor. Do not bypass the general agent with a private direct planner just because the first run was bad.
201. **Parallel connector research needs isolated runtime clients.** A shared `requests.Session` inside SerpAPI/Tavily clients is the wrong object to fan out across business-slot threads. Parallel workers should create fresh clients from shared config, while the materialized request/result rows preserve one ordered research plan.
202. **Agent tool scope is an organization contract, not a tool blacklist.** A business-memory answer can use broad market, peer, platform, and retained-memory tools when they help explain the requested company. Keep the call inside the shared AQL/Zopedia agent and make it organize evidence as primary company, adjacent business context, and wider spillover instead of narrowing the catalog or suppressing useful recall.
203. **Wandering is an engine-harness problem.** AQL/Zopedia should be able to handle named-company business research with the full shared tool catalog. When it drifts into unrelated tickers or broad market discovery, add semantic trajectory monitoring, stronger task/context prompts, and traversal requirements at the shared agent boundary instead of feature-local tool filters.
204. **Good business research needs organized spillover recall.** Blue Owl/OBDC research should naturally recall first-degree and second-degree private-credit/BDC neighbors, sector dynamics, rates, credit-cycle pressure, and parent-platform context. That is useful, not noise, if the agent keeps OBDC as the center of gravity, stays inside the job boundary, and labels why each adjacent item matters.
205. **Long Zopedia/AQL jobs need a visible research journal.** For one-hour background research, silence is a product failure. Log high-level planner rationale, tool starts/completions, source previews, redirects, monitor decisions, gaps, and final status. Do not log raw hidden chain-of-thought; log observable research state and concise rationale.
206. **Tool use is a research cost, not the product metric.** Background business research should spend calls when that helps recover from weak seeds, open better sources, or understand adjacent context. Budgets keep the job bounded; they are not a reason to add brittle preflight gates or trade away answer quality.
207. **Separate source acquisition from judgment inside AQL/Zopedia.** Connector/browser/crawler work should first materialize candidate evidence rows. Then a structured AQL/Zopedia synthesis should organize only those supplied sources into findings, gaps, and confidence before any story or wiki fact is written. This keeps the agent general while preventing it from wandering away from evidence it already found.
208. **Recovered identity must update the artifact identity.** A weak ticker seed can be resolved during planning, dossier synthesis, or final stack synthesis. When Zopedia resolves the company name from evidence, the materialized stack row, proposal, and story should use that recovered identity instead of leaving the row labeled as an unresolved ticker.
209. **Premium investor commentary is a research-direction source class.** Seeking Alpha and similar sources should be planned by the shared AQL/Zopedia research planner, opened through the shared authenticated browser/crawler path, and used to sharpen bull/bear questions and verification targets. They should not become final authority unless the opened source contains direct company evidence and passes the shared page-quality gates.
210. **Polite crawling needs endpoint-keyed throttles, not low global parallelism.** Background research can run many independent search threads when requests fan out across different hosts and providers. Politeness should be enforced by provider and hostname cadence, so `sec.gov` waits behind `sec.gov` and SerpAPI waits behind SerpAPI without blocking unrelated endpoints.
211. **Attention feed enrichment must enter the payload contract.** Building Zopedia business stacks and news-business resolutions upstream is not enough. The homepage must attach those rows to home items and bundle snapshots before summary/rendering, and unresolved trigger state should clear the raw why fields instead of becoming prose.
212. **Prefer targeted probes before full jobs.** Full scheduled pipeline runs are expensive, slow, and harder to debug. When possible, iterate with the smallest callable unit, synthetic frames, latest materialized-frame replays, render-preview text extraction, and focused LLM calls. Run the full job only when the local contract and qualitative output already look right.
213. **Attention research needs widening-circle recall.** Exact ticker news is only the first pass. If a basket moves together, AQL/Zopedia should search adjacent sector themes, private-company leaders, IPO speculation, rates, liquidity, policy, customers, suppliers, and peers before calling the move unexplained. The homepage should show the observed move while that research runs, not fill space with absence language.
214. **Materialized snapshot builders should be batch, local, and research-free.** After agent enrichment completes, persistence should not re-scan large frames per symbol or call hidden internet/model helpers. Build per-symbol maps once for prices, news, attention context, taxonomy, and share counts; leave live business interpretation to Zopedia/AQL.
215. **Failing closed still needs a product boundary.** UI-facing materialized rows should carry a short unavailable state and no raw failed-agent trace. Evidence packs, monitor decisions, and tool-budget details belong in AQL/Zopedia debug artifacts; page summaries should never become a dump of the failed run.
216. **Freshness is part of the evidence contract.** Search snippets, crawled pages, and news rows must preserve or infer `published_at` before synthesis. Old dated evidence can inform background context, but only same-day/recent evidence should drive Home attention titles, why-today fields, and supported-cause labels.
217. **Cold-start latency needs cache-aware diagnosis.** A first materialized Home load can spend seconds on metadata/blob setup while repeated loads are effectively instant. Measure first-load and warm-load separately before blaming the renderer, and increase cache horizons only after confirming the data path is materialized.
218. **Render paths must be read-only by default.** Product pages should load materialized state and render it. Expensive media, LLM, crawler, or provider work should happen in scheduled jobs or explicit actions; otherwise the UI becomes slow, refresh-prone, and hard to reason about.
219. **Primary feeds should persist before optional enrichment waits.** A background job can spend real time on AQL/Zopedia research, but independent page summaries should run with visible per-task progress and enough concurrency that they do not delay the core Home payload, ticker snapshots, or market feed.
220. **Pipeline persistence needs schema hardening.** Long research jobs should not fail at the final Parquet write because a provider returned mixed scalar types. Normalize heterogeneous object columns at the shared persistence boundary, while preserving typed source fields where they are already consistent.
221. **Optional tracking needs a full bounded lifecycle.** A DB sink is only optional if connect, schema bootstrap, job-start, progress, and job-end writes all have time bounds or failure isolation. Bounding only connection still leaves scheduled product work exposed to infrastructure locks.
222. **Freshness gates must cover every current-feed artifact.** The current Home story, research bundle, persisted search-news table, ticker background snapshot, and page summary context all feed the product. Apply the same recent/same-day evidence contract at each materialization boundary, otherwise stale rows can re-enter through a secondary surface.
223. **Absence prose is a state, not a sentence.** "No clear catalyst" and similar language should become structured status, hidden why text, or a concrete watch-next gap. The agent should still search widely for a cause, but the product should not render the absence as the story.
224. **Feed density should yield to story quality.** A homepage with fewer cards is better than one padded by pure ticker/percent recaps or empty unresolved rows. The display contract should require substantive business, sector, macro, or source-backed text before a card consumes attention.

226. **Cache materialized agent output by dataset version.** Streamlit session caches are useful for fast renders, but they must follow the materialized artifact identity. Use dataset version ids, run ids, or as-of timestamps in cache keys so a newly published Zopedia/AQL result replaces the old one without requiring a fresh browser session.
227. **Current-driver precision must be earned.** If Zopedia/AQL has evidence for a broad sector or risk-on rally, the answer should say that. It should only name a precise macro, geopolitical, or policy cause when recent evidence directly ties that force to the ticker, peer group, sector, or market move.
228. **UI-facing summaries need a public payload contract.** A materialized summary row can be produced by AQL/Zopedia while still excluding agent traces from the display artifact. Keep tool calls, evidence packs, and monitor decisions in debug artifacts; store only headline, summary, watch items, gaps, confidence, and status in the UI row.
229. **Tool schemas are part of the agent harness.** LLM planners can occasionally encode a valid intent with the wrong JSON value kind or an empty tool name. The shared Zopedia/AQL harness should repair against the advertised tool schema or restart the planner with the available tool list, instead of counting that as research evidence or spending useful budget.
230. **Broad market synthesis should compose bounded Zopedia research.** One agent thread should not be asked to explain every homepage move from scratch. Run bounded ticker/event Zopedia research first, then have a final Zopedia/AQL synthesis organize those completed answers and use a small number of extra tool calls only for high-value gaps. 231. **Search backfill needs bounded parallel acquisition.** A current-feed job should not sit silently in sequential per-symbol search calls. Use the shared news acquisition function, but fan out with a small provider-safe worker count, per-symbol timeouts, and progress logs so one slow ticker cannot stall the homepage build.
232. **LLM quality monitors should judge contracts semantically.** If a market summary draft overstates proxies, narrates missing evidence, expands unsupported company names, or invents precision, use a Zopedia/AQL critic to review the draft against the evidence prompt and request revision. Do not solve this with phrase scans; the monitor should accept, reject, or revise based on meaning.
233. **Page summaries need numeric discipline.** Top-of-page summaries can use technical levels as context, but they must compare supplied numbers literally and must not turn a level into the driver. If close is below resistance, say near/below resistance; the story still belongs to business, sector, macro, or evidence-backed context.
234. **Quality monitors need sentence-level review for absence prose.** A broad-sector answer can still smuggle the old failure mode by contrasting the supported driver against missing company-specific evidence. The Zopedia/AQL critic should inspect each answer sentence, move evidence gaps into limitations, and revise or fail closed before the row becomes product copy.
235. **AQL candidate research should be parallel at the harness, not simplified at the agent.** If a background attention job spends minutes on one ticker before touching the rest, the fix is not to shorten the research question or reduce business context. Keep the full Zopedia/AQL research loop, but run independent candidates concurrently with provider-safe worker limits and stable output ordering.
236. **Public-surface review must own every display field.** Rewriting the title, what-changed, and why fields is not enough if `affected_assets_summary_text`, `surface_*`, bundle copies, or review-note fields can still reach Home, Market Explorer, or page summaries. 354. **MCP connection scope must be explicit.** A Codex MCP registration gives the development operator tools in their agent session; it does not connect the Spectral Nature runtime, its users, or its trading agent. An application integration needs an app-owned MCP client boundary, per-user OAuth lifecycle, remote tool discovery, authorization policy, auditable calls, and explicit separation between research and order execution.
355. **User-owned OAuth state needs environment identity.** A unique key of user, provider, and resource is insufficient when development and production have different redirect URIs. Scope connections, pending flows, and audit events by runtime environment so a dev authorization cannot replace production tokens for the same person.
356. **Remote tool annotations are not local authorization.** MCP `readOnlyHint` and `destructiveHint` describe server intent but do not define Spectral Nature's policy. Keep an application-owned, fail-closed classification; unknown tools remain unavailable, review tools require review intent, and execution requires a separate explicit confirmation.
357. **A boolean is not trade authorization.** Money-moving MCP calls need an atomically single-use ticket bound to the user, environment, connection, expiring reviewed-payload hash, and provider idempotency key. The generic tool invoker must be structurally unable to execute.
358. **Ambiguous brokerage transport failures are not retry prompts.** Once an order call begins, a timeout can mean accepted or rejected. Preserve the same provider reference, mark the result unknown, and reconcile open orders before any new action.
359. **Trading credentials need environment cryptographic isolation even when infrastructure is shared.** Separate deployment keys make one environment's ciphertext unusable in another. Session-only browser auth, CORS/XSRF protection, a default-off execution switch, and locked dependencies reduce the paths that can reach the credential.
360. **An isolated release must include source-level dependencies, not only imported files.** A clean Robinhood image contained the new store but omitted three small `auth_store` exports it called at runtime. Run the exact in-container schema path before enabling execution, and keep the kill switch off until that probe succeeds.
361. **A durable agent run should carry identity, not prompt text, across the executor boundary.** Create and authorize the user-owned run in the API, persist its bounded input and budget in Postgres, and start the private worker with an empty job request. The worker can claim the run by environment and queue order without leaking prompts, tokens, or provider settings into Azure overrides.
362. **Event sanitization includes prose, not only JSON keys.** Removing fields named `reasoning` is insufficient when planner rationale or critic internals can appear in a progress message. Persist a small product-owned event vocabulary and keep full provider thought out of both callbacks and the journal.
363. **Runtime schema checks must not compete with the runtime transaction.** Repeating idempotent DDL for every repository while another connection holds an open read transaction can deadlock one process against itself. Commit read transactions promptly, check schema readiness first, and keep schema evolution outside normal request/job paths.
364. **A critic's revised answer is authoritative even when its verdict says accept.** A model may return an accepted answer with repaired Markdown or clearer evidence boundaries. If the critic supplies `answer_markdown`, use it; gating the revision on a reject verdict silently discards the actual improvement.
365. **A frontend migration becomes real when one production-shaped path crosses every boundary.** Framework selection alone proves nothing. The deployed Home/Zopedia slice validated visual identity, typed DTOs, cookie/CSRF behavior, durable replay, exact job authorization, worker execution, qualitative answer quality, and refresh-safe state before any Streamlit route was retired.
366. **Frontend replacement does not require a second account system.** Streamlit and Next.js can share the same users, password hashes, memberships, lockouts, and session policy while the browser-facing frontend uses a thin API/BFF transport. Account ownership stays in the shared authentication service; transport-specific cookies and tokens are not a second backend.
367. **Authentication availability is not credential validity.** A database connection failure must become a service-unavailable result and HTTP 503, never an unknown-user or bad-password result. Otherwise a shared database incident makes every frontend look like the user's credentials changed and can pollute lockout accounting.
368. **Public health responses are allowlists, not serialized diagnostics.** Secret resolvers and provider diagnostics may contain resolved values, usernames, exception text, or nested implementation state. Public auth/readiness endpoints should construct a minimal boolean/status DTO and never return diagnostic objects by subtraction or convenience serialization.
369. **Bootstrap credentials initialize empty stores; they do not remain the account password.** Once a database user exists, the durable password hash is authoritative. A later mismatch with a Key Vault bootstrap secret is expected and must not trigger a password reset or account rewrite.
370. **Optional email configuration must not sit on the sign-in readiness path.** Login availability depends on the account store, not SMTP. Resolve email secrets only for admin/email operations or an explicit email-status probe so a missing or disabled mail credential cannot delay the login screen.
371. **One brokerage can require two product transports.** Robinhood's hosted MCP reaches agent-enabled accounts, while the app-session API reaches the user's main accounts. Keep both behind application-owned adapters and route the portfolio through a durable provider reference instead of pretending one transport covers every account.
372. **Multi-user trading clients cannot inherit a library's global session.** A process-global HTTP session and plaintext token file are acceptable SDK conveniences, not an application boundary. Use an isolated session per logical operation, encrypt persisted tokens, trust only provider hosts, and keep passwords session-only during verification.
373. **Portfolio visibility and trade authority are different scopes.** Authorized investors may see a projected, redacted snapshot of the master portfolio, but live positions and order execution must verify the connection owner inside the service. Hiding controls in the UI is not authorization.
374. **Batch trading needs one batch ticket and deterministic child identities.** Bind the full canonical order set to one expiring, atomically consumed confirmation. Derive each provider reference from the batch reference and position identity so partial completion is auditable and the confirmed batch cannot be replayed.
375. **Main-account pages should render snapshots, not brokerage sessions.** Explicit connect or refresh actions may contact the broker; ordinary Portfolio and Performance renders should use one redacted snapshot. This keeps pages stable, prevents hidden credential use, and gives investor projections the same source state as the admin view.
376. **A simulated authentication contract is not a working login.** Endpoint reachability, current reverse-engineered source, mocked token responses, encrypted persistence tests, and a healthy deployment still do not prove a provider accepts real credentials and completes device verification. Require one real development connection and successful account snapshot before calling broker authentication operational.
377. **Resolve the cheapest high-risk uncertainty first.** For an unofficial external integration, exercise the real authentication handshake and first read-only account call before building snapshots, portfolio routing, or money-moving workflows. Unit tests should include the HTTP serialization boundary—not only mocked provider payloads—because one inherited content type can invalidate the entire design.
376. **An unavailable directory is not an empty directory.** Administrative list operations must preserve auth-store unavailability through the service boundary so the UI can show a retryable outage. Returning an empty list fabricates a valid business state and makes intact users appear deleted.
377. **Capacity headroom and failure isolation solve different problems.** Moving B1ms to B2s raises the documented user-connection allowance from 35 to 414, but an unbounded analytical job can still consume a shared pool. Put account, session, invitation, admin, and run-coordination state on a control-plane server with separate roles and budgets; keep analytical state on the data plane.
378. **Azure PostgreSQL resizing needs a connection-parameter step.** Changing an existing Flexible Server compute product does not automatically revise the current `max_connections` setting. A resize runbook must set the intended supported value, plan for restart downtime, and verify application pool budgets afterward.
379. **A broker adapter is operational only when its indispensable read is current.** Robinhood account enumeration remained valid while its classic portfolio historicals route was gone. Pin the current source evidence, prove the exact read shape against a connected development account, and make optional asset collectors degrade independently.
380. **Robinhood's modern portfolio curve is a presentation payload with reliable nested fields.** The usable dollar series comes from the Bonfire performance route's `returns` line, with timestamps and dollar values under each point's cursor data. Layout coordinates and optional high-precision blocks are not time-series identities.
381. **Private brokerage APIs need one request governor, not scattered sleeps.** Serialize calls process-wide, use a stable application user agent, pace reads and writes differently, honor one shared 429 cooldown, retry only safe reads, and never replay a mutation after an ambiguous timeout.
382. **Persist opaque execution handles, not broker identities.** Snapshot rows can carry masked account labels and connection-bound hashes for accounts, positions, option legs, and lists. Exact account and instrument identifiers should be re-resolved live inside the owner-authorized service immediately before review and placement.
383. **A database boundary needs a secret-identity boundary.** Putting the control DSN in a vault readable by pipeline jobs would preserve the connection failure boundary but weaken the compromise boundary. Use a control-only vault and managed identity, attach it only to UI/API consumers, and let Container Apps resolve the secret reference without giving jobs vault access.
384. **Runtime readiness must not execute schema DDL.** A least-privilege role can own its application schema without receiving database-wide `CREATE`. Check required relations on request paths and reserve schema creation and reconciliation for an explicit migration command.
385. **Published SKU zones are not live capacity guarantees.** Azure listed B1ms support in Central US zones 1–3 while zone 1 provisioning returned `CapacityNotAvailable`. Keep names and bootstrap steps retry-safe, inspect the actual failure, and retry an equivalent zone without changing the architecture or cost.
386. **Ceres product identity comes from account and contract metadata, not route family.** Filter accounts by `accountType=FUTURES`, resolve each market contract, and use broker cost-basis fields for signed quantity and P/L. Quote bid/ask midpoint plus an explicit contract multiplier gives a defensible futures mark and notional without mixing prediction markets into the portfolio.
387. **Broker return semantics can be richer than chart endpoints expose.** When Robinhood supplies current value and a cash-flow-adjusted return but omits the start value, derive `start = current / (1 + return)` and keep the broker return authoritative. Using the first plotted value silently changes performance meaning when deposits or withdrawals occurred.
388. **A flaky brokerage needs durable stale-while-revalidate reads, not only a page snapshot.** Cache holdings, histories, metadata, and opportunity-set results independently with source timestamps and preserve the last successful value when one collector fails. Use live reads only where correctness requires them: trade eligibility, available quantity, quote collar, open orders, and final pre-submit validation.
389. **Development deployment is still a release decision for money-connected features.** Repository automation defaults do not replace the owner's requested checkpoint. Local acceptance and explicit user approval must precede any Robinhood development rollout; production continues to require its separate explicit permission.
390. **The frontend is a research workbench, not a chart gallery.** Spectral Nature's target combines Bloomberg-like information density, Jupyter-like reproducibility, VS Code-like workspace composition, and Claude Code-like agent collaboration. Feature parity defines what must survive, while shared artifacts, panes, explicit agent context, and isolated execution define how those capabilities compose.
391. **Chat is the interface; code is an agent artifact.** Users steer analysis, revisions, approvals, cancellation, and reruns through conversation. The agent authors notebook steps and Python inside an isolated sandbox, while the VS Code-like workspace exposes read-only code, diffs, logs, provenance, and outputs rather than giving users an editor or shell.
392. **Advanced visualizations are validated artifacts, not generated browser code.** The sandbox may compute any supported analysis, but it publishes typed datasets and an allowlisted renderer specification with provenance. A small portfolio can specialize by workload while sharing selection, design, export, and failure contracts; arbitrary model-generated JavaScript never executes in the product origin.
393. **Entity views must not pull global analytical artifacts.** A one-ticker chart downloading 1.45 million global rows is a data-boundary failure, not a frontend loading problem. Publish bounded deterministic partitions, cache only the resolved slice, and let large legacy artifacts fall back to an existing on-demand source instead of exhausting memory or latency budgets.
394. **Third-party renderers must bring their static CSS through the CSP.** Plotly rendered three SVG layers as ordinary document flow when its runtime-injected stylesheet was blocked. Bundle the maintained library stylesheet under `style-src 'self'`; do not weaken the CSP with `unsafe-inline` to repair layout.
395. **Hydration-dependent credential forms fail closed before JavaScript is ready.** A server-rendered form without a safe native action can submit its fields as URL query parameters if clicked before hydration. Keep submission disabled in the server snapshot and enable it through hydration-aware state before accepting credentials.
396. **Nonce CSP makes rendering mode an application-wide contract.** A statically prerendered Next.js route cannot carry the request nonce generated by middleware, so strict-dynamic blocks its client bundle and leaves an inert server shell. Force dynamic rendering at the root layout when every application route depends on per-request nonces, then verify the built route table and deployed HTML.
397. **An isolated image patch must patch the running base, not copy a dirty shared module.** Copying the current `data_access/layer.py` into an older API base imported unrelated Robinhood modules that the base did not contain. Apply the smallest verified diff to the exact base digest and copy only newly required leaf modules; startup and in-container route probes remain mandatory.
396. **A high-value flaky broker is an ingestion plane, not a render dependency.** Robinhood reads belong in one paced worker that merges into provider-owned local snapshots, series, and resources. The dashboard stays read-only and useful from the last good state; only execution revalidates live facts.
397. **Catalog discovery must precede historical fan-out.** Lists and screeners can mix small portfolios, market-wide universes, futures contracts, and other non-equity symbols. Inventory group sizes and asset types first, bound analytical eligibility, quote-resolve candidates, and retain oversized groups as metadata rather than pretending every discovered symbol is a backfill obligation.
398. **Flaky backfills should commit useful batches independently.** Persist each successful history batch, preserve the last good resource on later failure, and mark freshness/error state separately. One bad symbol or late request must not erase earlier collection work or the dashboard's last usable view.
399. **Visualization density is part of the analytical contract.** A contributor graph should preserve the full local dataset but render only the groups and members that materially explain the selected result. Real-data inspection, not synthetic correctness, decides whether a Sankey or ranking is readable.
400. **Broker workers share the application's secret identity but not its page lifecycle.** A separate process must resolve the same environment-scoped encryption key as the UI, while schema migration and provider calls remain outside Streamlit. Normalize worker summaries at the queue boundary so a successful sync cannot be reported as failed because of a timestamp serializer.
401. **Scientific portfolio visuals start with comparable statistical dimensions.** A one-day move plotted against lifetime P/L combines incompatible horizons. Selected-lookback return, trailing volatility, covariance risk contribution, drawdown, expected shortfall, and robust movement z-scores answer distinct questions without pretending they are one measure.
402. **Wide historical reshaping needs real-width validation.** In the installed pandas path, pivoting 471 symbol histories silently collapsed a 250-row time axis to two unique timestamps. Building one indexed series per symbol and concatenating them preserved 251 timestamps across all 471 columns. Small synthetic frames did not reveal the failure.
403. **Portfolio read access and execution authority are separate contracts.** Active members can read the complete local portfolio and analytics; active admins alone can change connections, request refreshes, review orders, or execute. Recheck admin membership when consuming a payload-bound ticket so revoked authority cannot survive in an earlier review.
404. **Historical preload follows open risk before catalog freshness.** Current holdings must be unioned with bounded list/screener symbols. Fingerprint that required holding set and, while the larger catalog marker is fresh, fetch only holdings still missing history instead of waiting a week or replaying the full catalog.
405. **A frontend transport foundation is not a product milestone.** One authenticated chart proves cookies, BFF routing, serialization, and renderer loading. It says nothing about feature parity, information architecture, conversation flow, or visual quality. Report those layers separately and never let a working boundary inherit the status of the product built on it.
406. **Frontend migration begins with a feature ledger and side-by-side inspection.** Routes alone undercount the product. Inventory each current action, artifact, state, and cross-surface handoff, then translate them into the target workbench model before implementation. A route is migrated only when every old capability is preserved, deliberately retired, or visibly deferred.
407. **A chat-first workbench needs one clear conversation owner at every width.** Analytical routes can keep a persistent conversation rail, while the Zopedia new-thread canvas can own conversation directly. Do not render two competing composers just to make chat globally present; on smaller screens the same conversation becomes an always-reachable dock without creating a second product path.
408. **Durable event polling must merge by event identity.** Two overlapping refreshes can receive the same `after_sequence` window before either response advances the local cursor. Append-only client state then duplicates the research journal even though the backend log is correct. Merge by durable event id, sort by sequence, and advance the cursor monotonically.
409. **Concurrent same-origin mutations need one CSRF token acquisition.** Two client requests that independently call the token endpoint can both observe an empty cookie, mint different values, and leave one request holding a header that no longer matches the final cookie. Share the in-flight token promise, cache the issued value, and refresh once only for the explicit token-mismatch response.
410. **A local-data deployment includes the target environment's control state.** A healthy UI image and compiled analytics modules do not make cached brokerage charts visible when the target environment has no schema, connection, snapshot, or worker. Check each layer explicitly and report an environment-scoped connection as pending rather than copying credentials or financial rows.
411. **Schema bootstrap and recurring brokerage sync are different jobs.** Run DDL through a one-time migration execution, prove the relations exist, then restore the scheduled image to a non-DDL command. The recurring worker should serialize reads, apply application freshness rules, and avoid platform retries that can amplify pressure on a fragile provider.
412. **ML read models should summarize uncertainty without shipping raw simulations.** A forecast surface needs probabilities, expected returns, analog counts, and bounded percentile bands. Thousands of simulated paths belong behind the presentation boundary unless a specific artifact requests them; sending them with every entity page increases latency and exposes implementation detail without improving the decision surface.
413. **Retained media belongs on a media route, not inside a page DTO.** Home can advertise that its persisted narration exists, while the browser fetches bounded audio bytes only when needed. This keeps the core report cacheable and small, preserves content-type and nosniff controls, and allows historical replay to address the matching recording explicitly.
414. **A scoped image overlay must validate the inherited call graph.** Importing replacement modules proves syntax and top-level dependencies, but not compatibility with callers retained from the base image. Enumerate every changed public signature against the actual running base, exercise the authenticated route, and keep security parameters required rather than weakening the callee for backward compatibility.
415. **Queued ingestion is user-visible portfolio state.** Once a portfolio is linked to a provider-owned local data plane, `queued` and `running` refreshes must map to one explicit `in_progress` read state before the first snapshot exists and during later refreshes. The page may keep showing a last-good snapshot, but it must not silently fall through to another broker while the selected provider is materializing.
416. **Performance-tail views rank the full eligible universe.** A comparison selector answers “which series should I overlay”; it must not silently define the candidate universe for a best/worst view. Rank every analytics-ready group on the selected lookback, keep the strongest and weakest tails balanced, label their realized returns, and let the user control tail depth without reopening an unreadable full-catalog graph.
417. **A derived job image inherits its base entrypoint.** Replacing `CMD` alone can append a new command to an existing executable and fail before application startup. Inspect or explicitly reset `ENTRYPOINT`, keep the environment-specific command owned by the final image, and prove it with an empty-queue execution before relying on the schedule.
418. **A taxonomy catalog is one read model, not hundreds of helper calls.** Market lens labels, descriptions, counts, and memberships must resolve from one loaded taxonomy snapshot. Calling independently cached helpers inside a lens loop repeats database or blob access, makes the UI timeout proportional to catalog size, and can mix versions inside one response.
419. **Model-authored tables require an explicit Markdown dialect.** Preserving line structure is necessary but not sufficient: the frontend renderer must enable the same table syntax the research writer emits and wrap wide tables responsively. Otherwise a correct stored answer still appears as raw pipe text in the product.
420. **Cloud build context is part of release engineering.** Do not assume a hosted registry build honors the local Docker ignore file. Stage an explicit minimal context, inspect its size, and build immutable tags from that directory so caches, virtual environments, notebooks, and unrelated dirty files cannot enter the upload or image boundary.
421. **Inline intelligence belongs in the materialized page read model.** A feed that requires a separate ticker request for every visible company is neither fast nor information-dense. Join bounded price and fundamental snapshots during materialization, embed the public subset in the Home artifact, and keep the detail route as an optional drill-down.
422. **Mixed-frequency macro comparison needs an explicit transformation contract.** Normalize each series to monthly-last observations, transform rate-like series with differences and positive level series with percent changes, avoid forward fill, and record pairwise sample counts. A heatmap without those choices is visually persuasive but analytically ambiguous.
423. **First-load performance spans infrastructure and rendering.** Lazy-loading an off-screen visualization removes browser work, but a zero-minimum web or API replica can still impose a platform cold start. Measure both paths and keep a warm replica for an interactive development workbench when immediate first use matters.
424. **Deterministic page data and qualitative synthesis need separate release clocks.** Price, return, and fundamental snapshots should refresh from bounded materialized inputs without waiting for narrative research, optional knowledge enrichment, or a public-copy review. The complete Home build may embed the same snapshot, but an independent materializer keeps current market intelligence available when a model provider is slow or transiently fails.
425. **Choosing explanatory charts is different from choosing movers.** Give AQL the day's actual narrative context and dated price, financial, and macro candidates; ask it to select complementary decision questions and a series that directly visualizes each insight. Review real selections for causal overreach and leaderboard repetition. Keep values and complete plotted series outside model authorship.
426. **A knowledge browser and a research retriever need different result contracts.** Broad lexical fallback can be useful during research but makes a failed user search look broken when unrelated pages appear. A browser should return matching indexed pages, preserve query state, distinguish sources from synthesized knowledge, and expose real outgoing links and backlinks.
427. **Namespace copies must migrate the entire dataset read contract.** Copying the main Parquet and manifest but not the symbol partitions leaves large artifacts unreadable through the deliberately bounded dashboard path. Relocate every partition into the destination namespace, or build legacy partitions before publishing the destination pointer; never solve this by widening browser full scans.
428. **Model evidence and chart histories must be identical.** Supply every plotted observation and the displayed range/count; use a bounded daily mini-chart history instead of giving the model an excerpt of a different, longer chart. Keep full analytical histories in their dedicated workspaces.
429. **Opaque knowledge IDs are not path segments.** Stored source IDs can contain slash/colon separators. Carry them as encoded query values through BFF and private API; verify a real slash-containing ID through deployed ingress, not just the service function.
430. **Authentication availability is not authentication rejection.** Preserve cookies on refresh timeouts, rate limits, and server errors; only an explicit rejection signs the user out. Coalesce shell/route session reads without caching identity indefinitely, and verify a real expired-token reload.
431. **Production readiness includes producer/consumer compatibility.** A current artifact can still lack the fields and partitions required by a new frontend. Audit stable manifests and actual bounded read models; promote the existing owning jobs rather than introducing a duplicate refresh pipeline.
432. **Promote existing jobs through their versioned template, not a full resource replacement.** Template-only JSON Merge PATCH preserves schedules and write-only native secrets. Version-matched ARM reads avoid SDK display/read-only fields, and immutable release directories preserve the original rollback state.
433. **Partition acceptance must include the full producer's peak memory.** Migrating an existing table proves the format, not the scheduled computation-plus-serialization path. Release per-symbol histories after concatenation, share unchanged numeric columns, and group row positions instead of sorting another full table; review real-scale RSS before managed execution.
434. **Account parity includes consuming links, not just issuing them.** Preserve the native root-query invitation/reset contract across a frontend swap. Keep tokens and delivery diagnostics behind the BFF, consume single-use tokens atomically, reject invalid tokens before expensive hashing, and bound recovery requests in the shared control store.
435. **A correct series reference does not make its interpretation correct.** Seasonal peak comparisons can invent deterioration and a caption can borrow an adjacent series' dates. Give the shared AQL reviewer the exact selected histories and daily context, allow bounded selection revision, fail closed on unresolved meaning, and still personally compare the actual result with its sources.
436. **Validate login destinations after URL normalization.** A leading slash is not a same-origin guarantee: browsers normalize backslashes and strip some controls before resolving the host. Parse the destination against an inert fixed origin, compare origins, and return only the normalized local path, query and fragment.
437. **Revision needs the rejected draft, not just its objections.** A critic's issues without the actual prior output can restart selection and introduce unrelated errors. Preserve the exact draft alongside the review, correct unsupported claims while retaining grounded findings, and expose the declared review issues in internal progress diagnostics.
438. **An ARM PATCH contract includes its accepted media type.** Container Apps jobs accept template-only PATCH with `application/json`, but reject `application/merge-patch+json`. Verify the resource after every update; do not infer mutation from intent, an empty response, or general HTTP conventions.
439. **Provider failure is not permission to substitute accounts.** Select the broker from the shared portfolio linkage contract. A missing environment-owned connection, unavailable store, or pending snapshot must fail closed, not silently display another broker's account. Verify the actual provider and ownership during production acceptance.
440. **Schema existence does not imply read availability.** `ALTER TABLE ... IF NOT EXISTS` still queues exclusive locks. Skip complete schemas, close materialized reads before LLM/network work, identify pipeline sessions, and bound transaction lifetimes. Healthy workers and completed runs do not establish successful evidence retrieval.
441. **Separate frontend migration defects from existing backend state.** Compare the live and candidate runtime, store/schema, broker linkage, and independent prefetch results before calling for reconnection. A healthy scheduled worker can repeatedly process zero work; new credentials are not a frontend requirement.
442. **Preserve the production app identity when only replacing its frontend.** A template swap can retain generated hostnames, DNS, and managed certificates; keep old and new revisions on the same ingress port while warming. Capture exact rollback configuration first, remove backend credentials from the web runtime, and deny runtime access to retained managed identities.
443. **A verification exception does not establish that deployment failed.** Read actual state before retrying. Match the preparation client's versioned resource representation for fingerprints and compare identity lifecycle entries by identity ID, not array order. An advertised managed-identity endpoint also does not prove token access; verify denial for every retained identity.
