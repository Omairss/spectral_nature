# Advanced Visualization Architecture — 2026-10-02

Status: transport foundation implemented in an isolated development app; product presentation rejected. The versioned artifact contract, authorized Plotly registry path, and first Stock Investigator chart prove one transport path only. They do not constitute route parity or frontend completion. Broader parity and advanced adapters remain staged behind representative local, real-data evaluation.

## Decision

Advanced visualization is a typed artifact capability inside the chat-first research workbench. It is not a frontend page family and it is not arbitrary JavaScript generated by the agent.

The agent analyzes data and writes Python inside an isolated sandbox. A successful run emits versioned dataset and visualization artifacts. The API validates those artifacts, and the frontend chooses an allowlisted renderer through a small registry. Every renderer shares the same Spectral Nature design tokens, selection events, provenance drawer, export behavior, loading state, and failure state.

Feature parity comes first. Existing Plotly figures cross the new artifact boundary without being rewritten. New renderer families arrive after the parity path proves the common contract.

## Renderer Portfolio

| Adapter | Role | Initial policy |
| --- | --- | --- |
| Plotly.js | Existing chart parity and scientific 3D surfaces, meshes, volumes, and scatter | Keep existing figure JSON working; load dynamically; do not make Plotly the platform contract. |
| Vega-Lite | Default statistical and multivariate 2D grammar: distributions, heatmaps, small multiples, layered views, matrices, linked brushing | Accept schema-validated declarative specs bound only to platform dataset artifacts. Reject external URLs and unsupported expressions. |
| Perspective | Bloomberg-density tables, pivots, streaming market views, fast grouping/filtering, and chart-plus-grid inspection | Run a development integration spike before adoption. Use it as a read-only analytical viewer; analysis changes still originate in chat. |
| Sigma.js + Graphology | Zopedia knowledge graphs, relationship exploration, network-science overlays, traversal, clusters, and large 2D graphs | Use the current stable Sigma line. Compute expensive metrics and layouts in the sandbox or a worker; the browser renders and explores the result. |
| deck.gl | GPU-scale point clouds, dense heatmaps, spatial layers, large linked scatter views, and spatial/orthographic 3D | Use the production WebGL2 path. Keep WebGPU behind capability detection until deck.gl declares it production-ready. Prefer Arrow/binary attributes and level-of-detail artifacts. |

Three.js is not an initial platform dependency. Add a curated Three.js adapter only when a real analytical use case cannot be expressed by Plotly or deck.gl. D3 may be used internally by maintained adapters, but it is not an agent-facing renderer and does not justify accepting arbitrary browser code.

Official capability references:

- [Vega-Lite](https://vega.github.io/vega-lite/docs/) provides a JSON grammar for interactive, layered, and multi-view analytical graphics.
- [Perspective](https://github.com/finos/perspective) targets large real-time and streaming datasets with Arrow, WebAssembly, virtualized grids, charts, and React bindings.
- [Sigma.js](https://www.sigmajs.org/docs/) renders thousands of graph nodes and edges with WebGL on Graphology's graph model.
- [deck.gl](https://deck.gl/docs) provides layered high-performance WebGL/WebGPU visualization and supports binary data; its current documentation still marks WebGPU support as not production-ready.
- [Plotly.js 3D](https://plotly.com/javascript/3d-charts/) covers the scientific 3D families needed for parity and early advanced work.

## Artifact Contract

The frontend receives an envelope rather than application-specific chart objects:

```json
{
  "schema_version": "visualization.v1",
  "artifact_id": "viz_...",
  "renderer": "vega-lite",
  "renderer_contract": "v1",
  "dataset_refs": ["dataset_..."],
  "spec": {},
  "linked_selection_group": "company-comparison",
  "provenance": {
    "run_id": "run_...",
    "code_artifact_id": "code_...",
    "source_refs": []
  },
  "performance": {
    "row_count": 0,
    "delivery": "arrow",
    "level_of_detail": "full"
  }
}
```

The envelope owns identity, data references, renderer family, interaction group, provenance, performance hints, and export metadata. Renderer-specific configuration remains inside `spec`, pinned to the adapter contract and validated before persistence and again before rendering.

The frontend does not infer analytical meaning. Labels, units, scales, uncertainty, comparison basis, directed-edge semantics, severity, confidence, and source lineage must already be explicit in the artifact.

## Implemented Foundation

The first production-shaped vertical slice now crosses every intended boundary:

- `DatasetArtifact` and `VisualizationArtifact` are versioned backend contracts with content-derived identities, typed columns, provenance, and performance metadata.
- `POST /v1/visualization/{name}` reuses the existing chart registry and `query:execute` plus `chart:read` authorization instead of creating a second analytical backend.
- The Next.js same-origin BFF applies the existing session, refresh-token, origin, CSRF, path, and request-size controls before reaching the private API.
- The frontend renderer registry accepts only `visualization.v1` and `plotly.figure.v1`; Plotly is client-only, CSP-compatible through its bundled static stylesheet, and cannot expose its cloud-sharing control.
- Stock Investigator loads the real `technical_price_channel` chart through this path, keeps ticker/window deep links, and uses container-aware desktop/mobile layout.
- Large symbol-level reads no longer download the entire global price or technical-history artifact. New pipeline manifests publish 64 deterministic symbol-hash partitions; large legacy unpartitioned artifacts fail over to the existing on-demand data source.

This is an architectural foundation, not full Stock Investigator parity. The remaining Stock Investigator analyses and every other Streamlit route still need to migrate through the same contracts.

## Agent Flow

1. The user asks for an analysis in chat.
2. The agent identifies the required platform datasets and receives time-limited read scopes.
3. The isolated sandbox loads only those datasets and runs Python analysis.
4. The run emits a dataset artifact, an allowlisted visualization spec, the generated code/notebook artifact, and provenance.
5. The API validates schema, renderer, data scope, size, URLs, expressions, and resource limits before publishing the artifact.
6. The workbench dynamically loads the selected renderer and displays the result beside code, logs, sources, and narrative.
7. Hover, pan, zoom, and selection are direct interactions. A selection becomes explicit chat context only when the user asks the agent to reason about it or requests a follow-up action.

## Capability Routing

- **Word and semantic maps:** compute embeddings, dimensionality reduction, clusters, and labels in Python; render ordinary sets with Vega-Lite and very large sets with deck.gl. A word cloud is a curated template, not a separate application architecture.
- **Multivariate heatmaps and matrices:** Vega-Lite for normal analytical sizes; deck.gl aggregation for genuinely large dense point sets.
- **Knowledge and relationship graphs:** Graphology carries graph structure and algorithms; Sigma renders. Direction, edge type, confidence, severity, time, and source count remain first-class data.
- **Network science:** centrality, communities, paths, temporal slices, and uncertainty are computed in the sandbox and attached as graph attributes. The browser does not silently recompute business meaning.
- **Scientific 3D:** Plotly covers early scatter, surface, mesh, cone, streamtube, and isosurface work. deck.gl handles large spatial and layered scenes.
- **Financial terminal views:** Perspective is the leading candidate for fast streaming tables, pivots, grouping, and compact chart-grid views, subject to a styling, bundle, accessibility, and Next.js integration spike.
- **Linked analysis:** all adapters publish normalized selection events keyed by entity, time range, and dataset row identity. Workspace-level state coordinates cross-highlighting without coupling renderer internals.

## Performance Boundary

- Small results may use inline JSON. Large results use Arrow or immutable Parquet-backed artifacts.
- Do not send millions of rows to a renderer by default. The sandbox or data service produces aggregates, tiles, samples, and level-of-detail variants with the full artifact retained for follow-up analysis.
- Run parsing, layout, and heavy client transformations in web workers where the selected library supports them.
- Dynamically import each renderer only when its artifact is visible.
- Treat mobile as a separate resource budget, not a scaled-down desktop canvas.
- Record row count, encoded size, render time, interaction latency, and fallback reason so renderer decisions can be revised from evidence.

## Security Boundary

- No arbitrary HTML, JavaScript, React component, shader, package installation, or remote URL from a model response may execute in the product origin.
- Renderer names and versions come from a server-owned allowlist. Specifications are validated and size-bounded.
- Visualization data resolves through authorized artifact IDs; renderer specs cannot fetch the network directly.
- Sandbox execution has scoped read-only inputs, default-deny egress, CPU/RAM/time limits, an isolated filesystem, cancellation, and no production database, vault, broker, or application-host credentials.
- Generated exports are inert artifacts. If a future requirement genuinely needs a custom executable visualization, it must run on a separate cookieless origin inside a sandboxed iframe with a narrow `postMessage` protocol. It is not part of the initial design.

## Delivery Order

1. **Complete:** define `DatasetArtifact`, `VisualizationArtifact`, normalized selection events, and renderer-registry contracts.
2. **In progress:** build the Plotly adapter and move existing figures through it during feature parity. The technical price-channel vertical slice is complete.
3. Spike Vega-Lite and Perspective against real Market Explorer, Broad Economy, portfolio, and streaming-table payloads; keep only the adapters that meet visual, interaction, bundle, and accessibility quality.
4. Add Sigma/Graphology with a real Zopedia graph, including directed edges, evidence, confidence, and large-graph degradation behavior.
5. Add deck.gl with a real high-density multivariate or spatial workload and Arrow/binary delivery.
6. Enable agent-authored advanced visualization only after artifact validation, provenance, exports, and failure behavior are proven end to end in development.

No advanced renderer should be added merely because a demo looks impressive. Each adapter must retire a real product limitation and meet the shared artifact contract.
