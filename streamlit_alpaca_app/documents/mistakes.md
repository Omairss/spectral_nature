## Deploy & Operations

1. **Run `scripts/which_deploy.sh` before every deploy.** It tells you which container has changed files. Deploying the wrong one is a no-op that wastes 10 minutes.
2. **Prod promotion = image + runtime env.** When promoting dev to prod, diff env keys between the two apps. A missing env key makes a working feature look broken.
3. **Identity attachment runs on every update, not just create.** `az containerapp job update` does not reattach user-assigned identities automatically.
4. **Optional shell lookups return 0 with empty output.** Under `set -e`, a "not found" exit code kills the entire deploy script.
5. **Dev/prod behavioral differences must be explicit env vars**, visible in the deployment tracker. Never rely on code defaults or tribal memory.
## Verification & Testing

6. **Clear `.pyc` cache before trusting test results after module renames.** Stale bytecode files mask missing or renamed source modules. Tests pass locally while the deployed container (which builds from source) crashes with `ModuleNotFoundError`. After renaming, deleting, or moving any `.py` file, run `find . -name "__pycache__" -exec rm -rf {} +` and re-run tests.
7. **Verify the user-facing path, not just the service layer.** A passing unit test does not prove the homepage, the API endpoint, or the materialized view is correct.
7. **After deploy, test the exact affected screen or endpoint.** HTTP 200 on the health check is not enough.
8. **Raw SQL changes need a direct store-level test.** Service and API tests cannot catch a misaliased `FROM` clause.
9. **"Code exists" does not mean "feature is live."** Verify the deployment, the config, and the runtime dependency. Embedding client constructed ≠ embedding deployment provisioned.
10. **Test Azure features from inside the live container**, not from local CLI. Managed identity RBAC and CLI credentials are different.
11. **Use the project `.venv` for local pytest.** System Python can miss repo dependencies such as `networkx`, creating false failures and wasted debugging time.

## Secrets & Security

11. **Pre-commit hook scans for secrets.** Installed at `.git/hooks/pre-commit` via `scripts/scan_secrets.sh`. If it blocks your commit, the secret must be removed — not the hook.
12. **Auth fails closed.** When the auth store, Key Vault, or config is unavailable, deny access. Never fall back to anonymous.
13. **Notebooks, legacy folders, and docs are full secret-scan scope.** No file is "low risk."
14. **Secrets live in Key Vault. Config carries secret names, never values.**

## Data Pipeline

15. **Mandatory datasets fail the job. Optional datasets degrade gracefully.** A green job with stale output is worse than a failed job with a clear error. `_MANDATORY_DATASETS` in `attention_home_build.py` enforces this.
16. **One evidence trace contract for all research paths.** Every workflow that gathers evidence routes into `search_results -> source_documents -> evidence_chunks -> claims`. No parallel corpora.
17. **Raw observations are the source of truth. Summaries are cache.** Rebuild derived fields from the observation frame; do not trust a stale summary table.
18. **Retain full text, not just snippets.** When the fetch layer has richer content, carry it forward. A tight char cap turns page browsing into snippet collection. Do not truncate data by default. If text is genuinely too large and risks performance issues, use a generous limit and explicitly note that truncation occurred.
19. **Durable storage needs a read path immediately.** Storage without access traps value in implementation details.
20. **Chunks are the reasoning unit.** Document search alone is not "historical retrieval complete" when the runtime reasons over chunks.
21. **Match signals separate from rerank signals.** Lexical/semantic overlap decides whether a row matched. Authority and freshness refine ordering after.

## LLM & Narrative

22. **No hardcoded sentence templates for user-facing narrative.** Any string the user reads that contains a data value must be LLM-generated, not string-interpolated. No `f"Oil is {direction}"`.
23. **No if/elif dispatch for narrative variation.** Theme, direction, and intensity differences go into the LLM prompt, not branching code.
24. **LLM readiness is logged at startup.** `check_llm_readiness()` runs once per session. If embeddings show "disabled," `EMBEDDING_DEPLOYMENT` is not set.
25. **Generic phrasing is a quality signal.** `"with no clear catalyst"` or `"most plausible chain"` should trigger another research pass, not be accepted as final text.

## Agent Architecture

26. **Fix retention and retrieval before adding agent choreography.** Fancy orchestration does not rescue weak evidence.
27. **Fix the shared source contract.** Prefer a clear architectural correction over helper layers that conceal a broken acquisition or reasoning path.
28. **Agent tools must match the product promise.** If the feature promises search-backed analysis, the tools must include live search. The model cannot use tools it cannot see.
29. **Agent must search retained evidence before going external.** The SAA evidence store often already contains the answer. Zopedia was unable to find an obvious Avis short squeeze because it only did live web search and anomaly checks, missing 15+ articles already in the retained store. Always wire internal evidence search as a first-class tool.
30. **Live search must preserve the user's original query phrasing.** Intent classification strips domain-specific terms ("short squeeze" → "risk"). Pass the user's raw query to the search query builder so it reaches the web search API intact.
31. **Gated sources fail fast.** Fetch the page first, authenticate only when gated. Blocked login pages are fast-fail, not retry-loop.
30. **Match the ambition level of the request.** When the user asks for something ambitious, build the ambitious version — don't downgrade to the easiest thing that vaguely fits. "Agentic" doesn't mean "automated." "Dynamic" doesn't mean "fixed." The path of least resistance is often the wrong path when the ask is ambitious.
31. **Trading suggestions must fail closed without grounded synthesis.** Do not turn deterministic scanner scores into trade advice when the LLM or evidence path is unavailable. Show the data gap and require a grounded synthesis with invalidation and tail-risk fields.
32. **Do not create parallel research agents when AQL already owns evidence.** Page-level agentic summaries and trading synthesis must enter through the shared AQL / Zopedia agent path, then adapt the grounded result for the UI. A direct `llm.generate_json(page_data)` helper is a formatting shortcut, not a research agent.
33. **Do not add another Zopedia/AQL side path.** Before changing Zopedia, AQL, Attention summaries, SAA research, live research, or evidence packs, read `documents/reference/AQL_ZOPEDIA_ENGINE_GUARDRAILS.md`. New LLM/research behavior must become a mode or capability of the shared AQL/Zopedia engine, not another endpoint with partial memory/tool access.
34. **Do not discard completed research when a later planner turn is transiently empty.** The Broad Economy agent completed a grounded FRED tool call, then DeepSeek returned empty content on the next planning turn. Treat bounded empty/no-choice responses as recoverable once evidence exists, move to synthesis, and retain the failed call in telemetry instead of replacing the public page with failure prose.

## Azure

32. **Resolve subscription from the resource group, not from list order.** Multi-subscription credentials pick the wrong one silently.
33. **ARM fallback ids are for error reporting, not for scoring.** They must never count as discovered resources.
34. **Keep admin observability config separate from pipeline env** when the monitored resources are in a different resource group.

## UI & Product

33. **Start with the actions, then choose the container.** Per-row actions and state transitions first. Grid/table/card second.
37. **Conversational agents need conversation history.** If the UI is a chat model with follow-ups, the backend agent must receive prior turns. A bare follow-up string like "I mean the recent weeks" is meaningless without the prior exchange. Thread compact conversation context through the full call chain.
34. **Implementation details stay in docs, not on user screens.** If the text does not change what the next click should be, remove it.
35. **Loading states reuse real backend stages.** If the agent already emits progress events, surface them — do not invent a fake progress bar.
36. **Precompute expensive media in the scheduled job.** TTS, image generation, and heavy enrichment should not sit on the render path.
37. **Main features do not run on page load.** Page render should show cached/materialized data and explicit actions. Agentic/AQL work belongs behind a button or in a scheduled materialization job, not in a panel constructor.
38. **Do not fan out per-symbol metadata during table render.** Use materialized universe snapshots or a batch lookup for company names. A table with 80 symbols should not make 80 metadata calls just to fill labels.
40. **Multi-surface feature slices need one architecture pass.** If a TODO spans feed, summaries, and an agent, verify the existing job, data-access, and AQL patterns for all of them before editing. Do not fix one surface while leaving the same anti-pattern in the others.
41. **Materialized AQL steps need time bounds.** Bound acquisition, synthesis and advisory review in the shared engine. Preserve useful valid partial output and numerical artifacts when optional work fails; do not replace missing analysis with deterministic narrative templates.
42. **Materialized frame columns need stable types.** Empty strings in numeric columns can pass pandas tests but fail pyarrow during job persistence. Normalize optional numeric fields to numeric/null before returning job frames.
43. **Job images must include every module used by shared paths.** Reusing AQL from a pipeline job means the pipeline image must package AQL's dependencies, including data-access helpers. Local tests can pass while the container falls back if the Dockerfile omits a package directory.
44. **Timeout wrappers must return the same failure contract as the wrapped code.** A service can correctly convert AQL failures into a closed unavailable state, but an outer job timeout can still write raw error rows if it has its own payload. Scheduled summary timeouts should write the same explicit `unavailable` contract with `data_gaps`, not hardcoded fallback narrative.
45. **Do not render trading-agent evidence as raw JSON or clipped metric labels.** Candidate cards need full ticker/company identity, direction, confidence, key numeric context, invalidation, risk, and source trace. Raw expanders and narrow identity metrics make the agent look less grounded than the evidence it already has.
46. **Do not expose composite trading scores without decomposition.** A number like `Opportunity 88` looks arbitrary unless the UI shows the selected horizon, price action, momentum pace, trend quality, and missing fields that shaped the rank.
47. **Do not promote news aggregate fallback text into narrative slots.** Coverage-count lines are useful metadata, but repeating them as both Background and What Happened creates empty-looking context. Filter low-signal aggregate text before rendering narrative sections.
48. **Do not ship baseline company text with daily-news fallback language.** A monthly company-background dataset should not include sentences like "current narrative is still thin"; strip render-path/news-gap language so the baseline stays timeless and useful.
49. **Do not assume raising a display limit lengthens generated audio.** If the stored homepage summary already has a short `audio_text` and embedded TTS bytes, the UI will play that short clip until `attention-home-build` regenerates the snapshot. Remove source prompt constraints and rerun the job.
50. **Do not show raw provider policy errors in user-facing agent panels.** If an LLM provider rejects a generated prompt, translate it into an app-level message and log the raw detail elsewhere. Dumping `invalid_prompt` JSON makes the feature look broken and gives the user no fix path.
51. **Do not surface raw transport exceptions as agent output.** Errors like `RemoteDisconnected` usually mean a source closed an HTTP connection, not that the user's request is invalid. Retry once and show a concise "research source connection dropped" message if it repeats.
52. **Do not patch only the product-specific wrapper for shared agent failures.** The Trading Agent and Zopedia both use shared AQL/Zopedia paths. Transport cleanup has to live in the shared agent boundary and the UI error boundary, or another surface will still leak `RemoteDisconnected`.
53. **Do not deploy UI changes repeatedly without verifying the actual rendered page.** Syntax-checking and test-passing are not enough. Trace through what the user actually sees — identify duplicate components, missing data (enrichments not yet produced by the pipeline), and dead-end states ("not yet available"). Multiple blind deploys compound errors instead of fixing them.
53. **Match provider-swap scope to the request.** If the request is an agent-specific experiment, do not swap global `LLM_PROVIDER`. If the request is to change the LLM layer, do not hide it behind a scoped prefix. Global provider changes must update UI, API, jobs, tests, and deploy env together.
54. **Do not put Azure CLI on the request path.** A deployed app container may not include `az`, and installing it would still be the wrong fix for a page button. Runtime actions need SDK/ARM calls through the app identity, while precomputed summaries remain owned by scheduled jobs.
55. **Do not let deterministic routing block submitted chat requests.** The router can find symbols, releases, bundles, and confidence bands, but it should only enrich the agent request. If it classifies a message as search/ambiguous before the agent runs, one-word follow-ups like "yes" and broad questions both feel broken.
56. **Do not let LLM calls run unbounded inside an interactive agent.** The UI can keep emitting heartbeats while the request is still effectively stuck. Bound planner and final synthesis calls separately so a multi-tool query can return a degraded but useful answer instead of spinning forever.
56. **Do not scatter job trigger controls across feature pages.** Normal users should not see operational refresh buttons. Centralize job starts in Admin > Pipeline Jobs so feature pages stay read-only over materialized state.
57. **Trading action logs must be broker-aware even before execution is enabled.** A log-only Place decision should still record execution mode, broker, order payload, and broker order id fields so the later Alpaca API handoff does not require changing the audit contract.
58. **Do not call a multi-horizon materialized job complete until every required horizon has a usable row.** A job can succeed overall while one AQL horizon times out and leaves the UI empty for that horizon. Original recovery allowed grounded candidates or explicit low-confidence fallback candidates with data gaps. v0.6 supersedes this: every horizon needs an auditable run row, but candidate rows require gateway-governed research support.
59. **Do not spend bootstrap slots on low-yield search before required entity context.** A multi-ticker comparison that calls retained search first can exhaust its deterministic budget and miss one of the requested tickers. Seed all requested ticker contexts first, then add live or retained evidence.
60. **Do not feed rich materialized datasets to the LLM as generic objects.** If the summarizer only sees keys like `homepage_summary` and `top_events`, it may say current data is missing even though the payload contains the answer. Add dataset-specific context extraction at the shared tool-summary boundary.
61. **Do not leave live-search tools or prefetch fallbacks indistinguishable from hangs.** A status line like "Checking live event evidence" without elapsed-time heartbeats or a per-step timeout makes a slow vendor call look stuck. Hidden prefetch LLM calls can create the same failure before visible tools even start. Tool execution and preparation fallbacks need the same bounded, observable treatment as LLM planning.
63. **Do not keep dead LLM helpers as "just in case" code.** A presentation-layer helper that can call an LLM is still a future regression even if the active route no longer uses it. Delete it or move it behind AQL/Zopedia instead of leaving another shortcut for the next feature to reuse.
64. **Do not expose storage/job vocabulary as product copy.** Messages like "No materialized summary is available" or "scheduled AQL summary" make users debug the pipeline instead of using the product. Show the available user action and keep the operational cause in logs or Admin.
65. **Do not spend deterministic agent slots on low-priority memory search before required context.** Zopedia memory is valuable, but a direct CPI request or multi-ticker comparison should still collect the obvious dataset or all requested ticker contexts first. Add Zopedia after required seeds, or let the planner choose it.
66. **Do not claim YouTube transcript support is green from mocked parser tests alone.** Mocked captions prove parsing, not production retrieval. Real URL checks can fail from IP blocks; report that explicitly and keep pasted transcript ingestion as the reliable path.
67. **Do not let feature modules own raw model loading.** A direct `load_llm_client()` in a page, pipeline job, router, or helper is an orphan LLM path waiting to drift from Zopedia/AQL. Feature modules must enter through the named Zopedia runtime boundary, and tests should scan for new direct loaders.
68. **Do not let a Zopedia eval pass on tool presence alone.** A run that calls `zopedia.search_pages` can still be product-bad if the final answer says memory is missing, never reads the page, or hides page support. Eval gates must check the answer, evidence pack, and tool trace together.
69. **Do not rely only on strict full-text SQL for wiki memory search.** Long user prompts include filler words, eval tags, and phrasing not present in the page. If strict search returns no rows, use a bounded fallback candidate set before declaring memory missing.
70. **Do not replace LLM-native planning with hardcoded market query classifiers.** Keyword lists for "macro", "company", "current", or "broad market" are brittle shortcuts. Use the tool catalog, planner contract, and behavior evals instead; deterministic code should enforce evidence safety, not infer domain intent from word lists.
71. **Do not let fluent answers outrun evidence coverage.** The difficult-question probe showed answers that sounded complete after only `yield_curve_facts_1d` or `market_impact_map`. For complex questions, a plausible map is not evidence coverage; require a sufficiency check or state the missing evidence.
72. **Do not call Zopedia complete until parity primitives exist and are tested.** Search/read tools, wiki rows, and proposal storage are not enough. Original Zopedia parity requires community indexes/godnodes, backlinks, source/evidence tracing, page-read navigation, automatic guarded mutations, audit/rollback, review escalation, and answer-level evals that prove the agent uses those pieces.
73. **Do not reduce Zopedia memory improvement to review-only proposals.** The intended system should automatically commit safe, source-backed, reversible memory updates through typed APIs. Proposal/review flow is for escalation, not the default path for every improvement.
74. **Do not call a provider adapter a provider migration.** DeepSeek code support plus a scoped Zopedia env override is not a completed migration. A migration changes the shared provider boundary, removes conflicting scoped overrides, deploys UI/API/jobs with the same env, and verifies the real runtime config.
75. **Do not trust a dev deploy until runtime env is verified.** Passing `LLM_PROVIDER=deepseek` to a script can still leave Azure/OpenAI active if the script sources generated env afterward. Verify the actual Container App and job env after deploy, and fix the deploy script if command-line overrides are not authoritative.
76. **Do not stop source tracing at the source-list row.** A Zopedia `sources_for_page` result that only shows a title/URL still leaves the agent one step away from the evidence. Add a read-through operation before calling source provenance complete.
77. **Do not append common job env without de-duplicating job overrides.** Azure Container Apps rejects duplicate env names. If a scheduled job needs a specific value, such as a shorter `LLM_TIMEOUT_SECONDS`, the deploy script should let that job-specific value replace the common one.
79. **Do not confuse a fluent draft with a verified answer.** The first answer pass can sound confident even when evidence is thin. Run the judge at the shared Zopedia boundary so unsupported claims, false premises, and missing evidence can change the answer before any surface renders it.
80. **Do not call auto-improvement real if writes are not inspectable.** A Zopedia page update without affected page IDs, source evidence, before/after state, and rollback metadata is just a silent mutation. The write API must produce the audit record as part of the commit path.
81. **Do not leave rollback as documentation.** A rollback hint is only useful if the system can execute it through the same typed service boundary. Otherwise every bad automatic mutation still becomes a manual database repair.
82. **Do not add a maintenance engine without a job owner.** A service function that can build backlinks, communities, and issue reports is incomplete until scheduled jobs run it, UI/agents read the report, and deploy scripts create the job in dev.
83. **Do not let risky memory edits bypass review under an "automatic" label.** Automatic improvement means safe reversible commits. Destructive or ambiguous edits still need proposal escalation until judged executors are proven.
86. **Do not call a session chat feature durable because agent runs are logged.** Audit logs cannot resume a conversation cleanly. Store explicit chat threads and messages, then let run logs remain the evidence/audit layer.
87. **Do not make memory maintenance a visible manual control surface by default.** Search, mutations, proposals, and health are engine/admin state. The product surface should be chat, uploads, sources, traces, and automatic memory outcomes.
88. **Do not render synthetic eval URLs as clickable evidence.** Product eval fixtures may use URL-shaped identifiers for provenance, but citation UI must distinguish public web sources from internal/debug refs. A dead `eval.local` card makes the answer look less grounded than no card.
89. **Do not make chat history a raw picker.** A selectbox of thread IDs/timestamps is an implementation shortcut. History needs visible titles, current-thread state, direct open actions, and eventually rename/delete controls.
90. **Do not dump agent answers as one inert Markdown blob.** Dense answer text should be structured by the agent and rendered in selectable passages. The UI should let a user expand and drill into the exact text that raised the next question.
91. **Do not make answer actions louder than the answer.** Turning every paragraph into an `Open:` or `Go deeper` button makes Zopedia unreadable. Render the answer first, then expose deeper actions sparingly.
92. **Do not show unrelated lookup cards after a synthesized answer.** Omnibar search results are useful before synthesis, but stale or loosely related cards under a completed Zopedia answer look like bogus evidence.
93. **Do not let single-source answers claim high confidence.** If only one evidence source returns usable data, cap confidence and state the evidence gap instead of letting fluent synthesis sound more certain than coverage allows.
94. **Do not call mobile remediation complete from overflow checks alone.** A screenshot can have zero horizontal overflow and still be product-bad if the first viewport is redundant controls or a dense graph. Inspect the rendered screenshots against the page goal before deploying.
95. **Do not deploy feature-flagged UI code without verifying runtime env.** A successful image deploy can still leave the feature disabled if the Container App env lacks the flag. Check the deployed env after every feature-flagged rollout.
97. **Do not turn every product affordance into a visible button.** Zopedia became cluttered because navigation, history, source attach, admin, and row selection were all rendered as large explicit actions. Rows, drawers, tabs, chips, and contextual affordances should carry secondary interactions so the conversation remains the product.
98. **Do not leave multiple competing roadmaps in one plan.** Zopedia's plan drifted because it had stale "chat-first" claims, several execution orders, and an outdated next step. A serious execution plan needs one status, one canonical roadmap, one immediate blocker, and explicit no-go gates.
99. **Do not describe implemented foundations as if they are missing.** Zopedia already has judge, memory reflection, typed mutations, proposals, rollback, and maintenance job paths. Remaining work should be framed as eval coverage, hardening, and product proof, not as building those systems from zero.
100. **Do not let user rescue stay trapped in one chat thread.** If a user has to guide Zopedia step by step from a wrong "cannot query data" answer to a working tool path, that correction must become a durable learning event, regression eval, and planner/memory improvement. Otherwise the system is conversational but not self-improving.
101. **Do not call an anti-fragile plan executable without a contract.** A list of learning-loop ideas is not enough. The plan needs schema, service boundary, state machine, eval artifact path, job wiring, and measurable gates before engineering can implement it without redesign.
102. **Do not stop at the first passing benchmark answer.** The bond-yield benchmark passed only after fixing source contracts, row-preview visibility, recovery gates, and learning-job persistence. A fluent answer without a durable eval and learning event would have repeated the same failure later.
103. **Do not treat deployment script completion as job proof.** Creating or updating a Container Apps job is not the same as running it. Start one execution, inspect logs/counts, and verify provider env before calling a scheduled learning loop wired.
104. **Do not leave learning events in generated/applied limbo.** A self-improvement loop that never promotes events to `verified` or `regressed` cannot tell whether it actually improved future behavior.
105. **Do not let Zopedia become another feature-specific endpoint.** After deciding that AQL/Zopedia is the LLM-native research boundary, live research, homepage summaries, page summaries, evidence packs, critique, and chat should enter through one engine contract. Keeping separate orchestration paths creates partial access, inconsistent memory/tool behavior, and repeated "not fully wired" failures.
106. **Do not let analysis code-generation failures masquerade as missing data.** The Zopedia thread `zthread_0160c291543e474d` showed `analysis.run_python` rejecting flattened one-line Python and stringified `dataset_refs`, then the final answer claimed individual-stock correlation data was unavailable. Analysis tool boundaries must normalize safe argument drift, run one repair pass for `analysis_code_error` / `analysis_input_missing` / `analysis_runtime_error`, and preserve the real failure category if repair still fails.
107. **Do not call analysis repair fixed until the repaired code executes.** The same thread later showed the repair pass running but still returning rejected code because generated indentation, pandas method safety, inline dataset JSON, and date dtype handling were not fully covered. The repair boundary must retry within a small budget, use actual input profiles, normalize generic generated-code indentation defects, and return the final failure if execution still cannot succeed.
108. **Do not put long sequential work inside a tool that has a shorter outer timeout.** `research.live_event_evidence` was doing helper LLM classification, LLM query rewriting, SerpApi, Tavily, and symbol-news searches before returning, so the agent killed it and lost all partial news. 109. **Do not make the LLM infer a long-term trend from a sample preview.** In the long-term trend thread, `price_history` returned 252 rows for APLD, but the answer described only the first three sample rows. Tool summaries for time series must state full window coverage, first/latest values, and computed return; otherwise the preview can become false evidence.
110. **Do not inject raw logs into LLM context by default.** `analysis.run_python` used to append raw stdout into `llm_context_text`, so a simple print could crowd out evidence in every later prompt. Keep raw output persisted for audit/debug, but feed the agent summaries unless it explicitly asks for raw logs.
111. **Do not call visible reasoning/status prose the problem.** The Zopedia trace is a core UX feature. The failure mode is ugly rendering, malformed tables, and raw-looking layout. Preserve the trace and make it feel designed.
112. **Do not leave old agent endpoints as callable escape hatches.** A renamed product can still be architecturally wrong if scripts or jobs import the old chat agent directly. Remove the public symbol and add a scan that forces every product surface back through AQL/Zopedia.
113. **Do not verify mobile defaults only through `?layout=mobile`.** A query-param screenshot proves the mobile renderer works, not that a real iPhone reaches it from the normal URL. Verify the deployed normal URL with an iPhone user agent and inspect the runtime env before calling mobile fixed.
114. **Do not let a later dev deploy revert mobile layout env.** The iPhone path regressed because the live dev revision had `STREAMLIT_LAYOUT_MODE_DEFAULT=desktop`. Mobile rollout settings need deploy-script defaults and post-deploy env verification, not one-off Azure edits.
115. **Do not fix mobile by making desktop mobile.** Setting `STREAMLIT_LAYOUT_MODE_DEFAULT=mobile` globally routes desktop browsers into the phone shell. Mobile fixes must verify both desktop and phone viewports before calling the rollout done.
116. **Do not put operational recovery controls on Broad Economy.** A missing Broad Economy Zopedia Summary is a job/materialization failure, not a user workflow. Do not add `Load FRED Data`, `Run FRED Job`, or `Analyze in Zopedia` controls to the page; fix the macro job and lookup contract, then verify the rendered dashboard.
117. **Do not let a newer partial page-summary artifact mask an older valid surface summary.** `page_agentic_summaries` can be written by separate jobs. A latest attention-home artifact with an unavailable Broad Economy row should not hide the valid Broad Economy row produced by the macro job.
118. **Do not answer codebase-cleanup questions with runtime token controls.** When the user asks whether a simplification plan is efficient, first inspect ownership duplication, wrappers, stale fallbacks, import direction, file size, test coverage, and deletion proof. Runtime LLM budgets are a different concern and should not be inserted unless explicitly requested.
119. **Do not call a rename complete while public contracts still use the old name.** API paths, auth scopes, docs, evidence-pack defaults, retained-memory provider strings, and boundary tests are part of the product architecture. If they still say Omnibar, the Zopedia migration is not clean.
120. **Do not let broad unit tests enter live enrichment or narration paths.** Attention-home unit tests that exercise dataset assembly must stub Zopedia enrichment and ElevenLabs narration unless the test is explicitly covering that integration. Otherwise a normal pytest run can block on provider IO instead of testing the local contract.
121. **Do not leave Postgres connection attempts unbounded.** Optional DB-backed helpers are supposed to degrade gracefully. If `psycopg.connect()` has no shared `connect_timeout`, a missing or slow database can freeze tests and product fallbacks before the graceful path ever runs.
122. **Do not let unit tests inherit local deployment connectivity.** A local Key Vault or Postgres config can make a no-DB test commit real Zopedia rows, and a default-enabled evidence pass can call the agent loop during a summary sequence test. Tests that assert isolated contracts must disable or inject those dependencies directly.
123. **Do not promote broad Zopedia context into company memory.** A runtime proof run showed market-theme pages being copied into ticker `Business Model` sections. Company memory must be sourced from company baselines, filings, fundamentals, source news, or trusted human/authored memory, not from generic theme/concept matches.
124. **Do not let generated memory recursively cite generated memory.** Once a weak generated draft exists, later cold-start runs can treat it as truth unless the resolver preserves original source markers and rejects self-referential summaries.
125. **Do not make business-model memory an event-side helper.** If business context is built only inside a news-resolution path, summaries and attention feeds cannot reuse it cleanly and every new surface is tempted to add side helpers. The ticker business model stack should be a first-class AQL/Zopedia artifact that event resolvers read.
126. **Do not call a business-first feature done when it only emits gaps.** The first ticker-stack pass created a clean row and synthetic example but did not force connector evidence collection or prove a real company story. Build the research plan/request/result artifacts first, then judge whether the story is good enough.
127. **Do not treat retrieval volume as retrieval quality.** The CRWV proof found that generic Similarweb and stock-quote results could satisfy a query lexically while saying nothing specific about CoreWeave's business. Historical qualification (October 14): the old restriction to promoted, company-specific facts was too narrow. Distinguish unrelated lexical matches from useful indirect evidence; the LLM may develop sector, customer, supplier and financing hypotheses without exact-company proof or a publication gate.
128. **Do not hide weak thinking in hedged walls of prose.** Long, cautious text can look responsible while avoiding the real job: make the business call, show the decisive evidence, and name only the concrete gaps. If the answer is mostly caveat or source-stitching, it is not ready.
129. **Do not confuse complexity with ambition.** Ambition means solving the real contract cleanly, not adding wrappers, side helpers, hardcoded escape hatches, or cosmetic UI/prose patches. If a fix does not reduce future failure modes, it is probably a band aid.
130. **Do not ship evidence labels as user-facing analysis.** Phrases like "quarterly-results evidence exists" or "Glassdoor sentiment evidence" are project pollution. They prove retrieval happened, not that the business was understood. Historical qualification (October 14): requiring a verdict or exact missing slot was too rigid. Explain practical meaning, plausible connections, alternatives and useful uncertainty in the form the question needs; do not impose a fixed verdict or prose template.
131. **Do not use phrase blacklists as product-quality guardrails.** A blacklist can make tests pass while preserving the broken behavior. If code can still synthesize pseudo-analysis with different words, the unsafe path remains. Remove the path or require the proper verdict-producing agent.
132. **Do not bypass Zopedia for business-memory synthesis.** If the task is to resolve a company story against the wiki, call the AQL/Zopedia agent. Direct feature-local LLM calls create parallel truth paths and can pollute project memory with ungrounded pseudo-analysis.

## Search Pipeline

37. **Hardcoded intent classifiers destroy domain-specific terms.** A 5-category enum ("oil/rates/defensives/risk/generic") mapped "short squeeze" to "risk" and then searched for SPY/QQQ. The LLM never saw the user's actual query. Classifiers must preserve the user's original phrasing through the search pipeline.
38. **Relevance gates scored against the classified theme, not the user's query.** When the classifier was wrong, the gate rejected every relevant article. Always check match against the user's original query terms as a bypass.
39. **Corrupted timestamps crash psycopg silently.** A year-48113 value in `published_at` crashed `cur.fetchall()` inside a `try/finally` (no `except`), making the function return empty. Cast timestamps to text in SELECTs when the table can contain corrupted data.
40. **Three-stage truncation (2600→1600→1600 chars) starves the LLM of evidence.** Each truncation point was independently "reasonable" but the cascade lost 60-80% of the evidence. Treat the full pipeline's truncation budget as one budget.
41. **Full narrative KG lookup creates false graph matches.** Long attention summaries fed directly into `search_knowledge_graph_nodes` matched unrelated nodes through generic context words. AQL needs a subject extractor and stopword/domain gates before KG traversal.

## Caching & Vendor

42. **Local cache is disposable. Blob + manifests are durable.** Cache caps and pruning belong in the shared cache helper, not in cleanup scripts.
43. **Vendor bulk endpoints are optional** when the stable per-series path still works. One broken auth key should not look like a full data outage.

1. **Do not turn comparison notes into roadmap recommendations without proof.** In the Zopedia comparison, "upstream" was unclear and "adapt Research Mode UX" overreached. 109. **Do not pin a new Flexible Server to the source zone without checking live capacity.** Both the restore attempt and first clean-create attempt spent minutes provisioning in Central US zone 1 before Azure returned `CapacityNotAvailable`.
