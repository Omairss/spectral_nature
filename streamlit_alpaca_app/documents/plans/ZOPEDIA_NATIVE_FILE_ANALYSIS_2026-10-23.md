# Zopedia native file analysis

October23,2026. The owner asked to finish external benchmark coverage and bring useful modeling capabilities into Zopedia. Financial DataFrame calculations and charts are already in production. FINCH, BlueFin and EMB additionally require native files that the existing calculation process cannot admit or produce.

The shared analysis owner gains `analysis.run_files`, available only when the caller attaches an owned file workspace. Input admission copies and hashes declared regular files; model arguments never select host paths, mounts, images, credentials or evaluator directories. Code executes in a nonroot Linux container with no network, a read-only root, bounded memory/CPU/processes and a512MiB temporary workspace. Input files and the one container runtime source file are read-only mounts. No application tree, provider key or Docker socket enters the executor.

The workspace survives successive analysis calls within one investigation. Native LibreOffice recalculation disables macros and external updates; models can use openpyxl or UNO according to the task. This capability does not promise preservation that the engine qualification failed to establish. Inspect original financial statements, formulas and visual elements personally; retain genuine compatibility failures.

Only regular output files under the owned output directory become artifacts, limited to24files and64MiB total. Artifacts have immutable invocation IDs, content hashes and retained bytes. Cancellation or timeout destroys the complete container, including descendant calculation processes. Context ownership keeps parallel investigations separate.

The first implementation and native benchmark condition live in the isolated `experiment/native-file-analysis-20261023` research checkout, based on the frozen shared research engine. It is not accepted release source. First qualify actual execution, cancellation, input/output boundaries and a native workflow. Then run retained public tasks through that same shared owner, with evaluator records absent from the actor workspace and final assessment performed by the primary agent.

The local Docker transport is a research executor. Production needs an isolated hosted transport, user/run-owned input and artifact storage, authenticated downloads and both client presentations before this file capability can be promoted. No local filesystem link is presented as a production download. Existing production calculation and chart behavior remains the accepted release until those paths are reviewed.
