# Market event calendar sources — October 30, 2026

Status: implemented on DEV on November 1, 2026. Alpha Vantage expected earnings and official Fed/BEA schedules plus BLS/FRED fallback now feed the shared native/web carousel. The owner key is stored in Key Vault. The first managed-identity cloud publication succeeded with 3,454 earnings and 61 agency records. Production is unchanged. See [implementation and current limits](LIVE_MARKET_CALENDAR_2026-11-01.md).

## Source decision

Use the originating agencies for US macro schedules, with FRED for release discovery and economic observations. Use company investor-relations calendars and earnings-date announcements as the primary authority for confirmed company dates, initially covering important names such as the Mag7 and the application's broader selected universe. Prefer published calendar/RSS feeds where offered; public announcements remain useful when a calendar page requires JavaScript. Do not equate an accessible website with an already-qualified automated adapter.

Evaluate Alpha Vantage's bulk earnings calendar for broader expected-date discovery. Its public demo works, but it does not provide a company-confirmed flag, and its standard license is personal/non-commercial. An entitlement and intended-use check is still needed before using it in a shared published application. Benzinga is an optional licensed alternative if broad coverage, update/removal contracts or commercial distribution later justify it; it is no longer the default source decision. Do not make calendar availability depend on a user's brokerage login.

## Alpaca coverage — November 1 review

Alpaca's documented [`/v2/calendar`](https://docs.alpaca.markets/us/v1.4.2/reference/getcalendar-1) supplies market days and opening/closing times, including early closes. This is useful for session boundaries. Its [corporate-actions endpoint](https://docs.alpaca.markets/us/reference/corporateactions-1) covers dividends, splits, mergers and related actions; the published supported-type list contains no earnings type. The current [API index](https://docs.alpaca.markets/us/llms.txt) and [MCP tool list](https://docs.alpaca.markets/us/docs/trading-api-mcp) did not expose an earnings-date or macro-release-calendar endpoint. An older version of the MCP description mentioned earnings under corporate actions, but that sentence is not an executable API contract. No authenticated Alpaca endpoint was called for this investigation.

- BLS ICS: HTTP 403 from this Mac. Documentation confirms the subscription, but this is not a successful runtime fetch.
- Federal Reserve calendar HTML: HTTP 200. The published monthly page separates meeting, press-conference and minutes entries and supplies times. The annual meeting page is not sufficient by itself for exact intraday times.
- Application Key Vault was queried for secret names only. A FRED match was present; no Benzinga, Finnhub or FMP match was present. No credential values were printed or retrieved. This does not prove the owner has no separate vendor account.

The sample prototype’s dates and outcome text have not been converted into live events. For example, the fictional November 4 FOMC entry is not supported by the official 2026 meeting schedule; it must never be migrated into serving data.

## Existing integrations and alternatives

`services/fred.py` already owns FRED authentication, retrying requests and observations. It currently has no upcoming-release adapter. Extend that owner rather than creating frontend provider calls.

`services/robinhood_mcp.py` lists `get_earnings_calendar` and `get_earnings_results` among foreground read tools. That allowlist is not proof of date coverage, confirmation fields, background eligibility or redistribution rights. It can be evaluated as a user-owned brokerage cross-check; the shared calendar should remain available independently of that connection.

[FMP’s stable calendar documentation](https://site.financialmodelingprep.com/developer/docs) and [Finnhub’s earnings-calendar documentation](https://finnhub.io/docs/api/earnings-calendar) were reviewed as alternatives. FMP documents an earnings calendar and report-time option. Finnhub separately advertises [commercial redistribution licensing](https://api.finnhub.io/pricing-startups-and-enterprise). Neither had a matching application credential in the October30 metadata inspected. The earlier Benzinga preference was based on documented confirmation, update and removal contracts without first exhausting free official/issuer sources; the November1 decision above supersedes that preference. Benzinga's [earnings API](https://docs.benzinga.com/api-reference/calendar-api/get-earnings) remains an unqualified licensed alternative, not an already-connected integration.

## Shared data design

One background ingestion path persists normalized calendar events for FastAPI, Next.js and SwiftUI. Render paths read the published calendar and never initiate provider requests or research.

Each event retains provider ID where available, source URL, issuer/release identity, fiscal/reference period, event kind, scheduled date, nullable exact timestamp, original timezone, timing precision (date/session/exact/approximate), confirmation status, provider update time where supplied, fetch time and revision history. Before-open/after-close and conference-call time do not establish an exact earnings-release time. Convert known instants through America/New_York and UTC with daylight-saving rules; preserve date-only values as dates. An issuer's approximately scheduled release is not an exact timestamp. Reconcile discovery and issuer records by issuer, event kind and fiscal period without merging release and call into one instant.

Group headline/core components of one economic release without merging separate earnings or the Fed’s decision and press conference. Reconcile reschedules by source identity and reporting period. Paginate complete date windows and record coverage. A failed or incomplete fetch must not erase previously known events. Benzinga’s [removed-events endpoint](https://docs.benzinga.com/api-reference/calendar-api/get-removed) supplies explicit removals/cancellations; retain their history instead of leaving obsolete events active.

Dates and numeric results come from source records. Shared AQL/Zopedia may produce concise display names, three-word past summaries and contextual importance from the actual release and existing research. It must not infer dates, release times or daily sentiment from wording. A scheduled time passing is not proof that results were published. Vendor importance can inform research ranking; picker perspective is a separate visual scale effect.

Poll schedules in the background with a rolling horizon and more frequent refresh near events, after checking vendor limits and actual request costs. Keep schedule freshness separate from publication of actual results. Existing production research budgets, providers and schedules remain unchanged until implementation is accepted and authorized for release.

Reconcile actual sample events against issuer/agency announcements, including DST and simultaneous releases. Test shared publication and each consumer only after the data path is real.
