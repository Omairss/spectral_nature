# October 16 release: scope and confirmed source regressions

This is a read-only audit of the reliability release, requested after the Home rollback was discovered. No application change, deployment, inference, research regeneration or product-data write was made during this audit. Production restoration remains unauthorized. **Restoring the Home worker alone would leave confirmed regressions elsewhere.**

## Deployment reach

The production receipt and current Azure image inventory agree: four applications and sixteen job templates received the release. The applications are both web frontends and the modern and legacy APIs. Fifteen jobs share the new common worker: universe, equities, macro, commodities, options, news, taxonomy, Home, quarterly fundamentals, company baselines, Trading, Zopedia maintenance, Zopedia learning, scheduled health and queued research. The sixteenth is Robinhood sync, which received its own image with the same broad application-source overlay.

Fifteen development targets also received the original combined release. Subsequent database-lifecycle work changed development images; the Home-only development restoration changed one manual job back to its accepted October 14 image. Neither action repaired production.

That development Home rollback also restores that image's earlier database implementation on the one manual job. Its prior database-lifecycle image, full job definition and scoped repair remain retained. All other database-repair deployments and the paused Trading work were preserved. No new execution was started by the Home image change.

Deployment reach does not mean every feature failed. The findings below distinguish removed behavior, directly broken contracts and measured current output from risks that have not been measured under a complete workload.

## Confirmed regressions

| Feature | Previously deployed behavior | October 16 result and evidence |
| --- | --- | --- |
| Home discovery, explanation and overview | The accepted Home producer considered the complete intake, jointly wrote the overview and stories, ran shared answer review and preserved generated prose. | An older producer and destructive text cleaner replaced it. Selection/review behavior regressed and sentences were deleted or cut. Current production has eight stories and no market overview. |
| Home's five key charts | The API accepted independently refreshed selections, chose the newer available set and retained a selection timestamp. | The API again requires the selection's Home run to match and returns nothing unless exactly five unique points survive. Five retained selections exist, but reference a different Home run; the current public response contains zero. `daily_datapoints_as_of` and per-point `selected_at` were removed. |
| Intraday price charts | The Home worker's Alpaca wrapper accepted the `adjustment` keyword used by intraday prefetch. | The copied wrapper no longer accepts that keyword, while the copied caller still supplies it. This fails before provider transport. Home catches the exception and proceeds with empty intraday input; the separate snapshot handler does not catch it at that boundary. All 34 ticker snapshots in the retained October 16 Home publication lack intraday points. The current API's 21 rendered ticker entries also contain none; 18 still have daily history. |
| Market-data memory handling | Equities converted raw bars one batch at a time, partitioned row positions and released intermediate technical-history frames. | The copied code again retains raw bars across the universe, copies/groups complete tables and retains intermediate histories during serialization. These lost safeguards increase memory pressure and OOM risk. No new stress run was performed, and this audit does not attribute a particular crash to them. |
| Market observation dates | Equities stamped each mover frame with `observed_at_utc`; materialized loaders retained/backfilled the observation time. | Both stamps and loader backfill disappeared. Current production has 999 daily movers and 586 macro movers with no row-level observation timestamp. Dataset-level publication/as-of metadata still exists. Downstream chronology loses the more precise observation contract. |
| Zopedia source indexing and maintenance | Shared workers built a source-page index once and ended the read transaction before constructing maintenance graphs. | The replacement removed the index, repeatedly scans the page collection and removed the explicit pre-computation commit/exception rollback. This is a confirmed loss of performance/transaction safeguards in maintenance and affected shared-worker consumers. Its contribution to total database saturation is unmeasured. The modern API already had the older implementation before this release, so its presence there is not a new API regression. |
| Robinhood refresh pacing | The dedicated sync image used hourly/two-hour cadence buckets and prevented a second scheduled request in the same bucket. | The shared overlay replaced this with the older 15-minute/two-hour rolling-age calculation and removed the recent-request exclusion. The Azure cron is still hourly; this does **not** establish four times as many scheduled executions. The accepted protection against completion-time drift and same-window duplicate requests was lost. Off-hours refreshes can skip a due boundary. |
| Scheduled monitoring and Home completion status | The health worker reconciled exact Azure executions with unfinished database runs, checked failures beyond Home/Trading and scoped job/provider reads by environment. Home propagated degraded research as a Warning. | Azure execution reconciliation and wider failure coverage were removed; reads reverted to narrower/unscoped forms. Home's wrapper stopped propagating its degraded-research result. The new receipt/index recovery does not replace those checks. Latest health executions succeeded, but that does not restore the removed coverage. An earlier new-image health execution also exhausted its platform window while draining recovery backlog. |

These are eight affected areas, not eight independent root causes. Several share the same overwritten modules.

## What the audit found preserved

- The production Trading producer's `services/trading_agent.py` is byte-identical to its immediate pre-release image. Its run handler, source-reference/checkpoint work and research execution recovery were retained, apart from operational entrypoint/connection changes. This does not insulate Trading from changed market data, shared Zopedia services or database load. The separate long/short and reasoning candidates remain held.
- The modern API retains its existing routes, including portfolio/list analytics, conversations and feature requests; its main route file adds Admin Health. Portfolio projection and Robinhood opportunity analytics match the immediate prior API. Authentication, invitation/reset and execution-permission logic in that API were retained; database connection ownership changed.
- Existing frontend page/component source is retained. The five changed frontend files are the Admin page, three new Admin Health files and shared CSS. The CSS also changes table-cell wrapping globally, so the frontend was not pixel-identical. The Home card and financial-chart renderers were not removed. Missing intraday charts originate in the backend contract above.
- The broker's existing order review/execution functions were not changed by the source comparison; the scheduling/store changes are real. This audit did not submit orders or exercise broker execution.
- Provider/model settings, cheap-model transport and the shared context serializer were preserved in the accepted release. The held premium-routing and hierarchy experiments were excluded. Their presence in the later repository checkpoint is not evidence that they ran in production.
- No stored conversations, research or portfolio history were deleted by this audit. The observed publication regressions concern generated/retrieved output; this is not a full forensic certification of every stored row. The stopped database and Trading implementations and their paid evidence remain archived and recoverable.

## Current runtime observation

The production public Home request returned HTTP 200 in about 1.3 seconds, serving run `46b3d391-91eb-4ae5-bd81-58ff09a66067`, observed at October 16, 13:50 PDT. It had eight stories, no overview, zero key charts and no intraday points in its 21 rendered ticker entries. Availability at this check does not erase the earlier HTTP 503/latency observations or establish sustained recovery. Database saturation was observed before the rollout; attributing all slow loading to the rollback would be unsupported.

The latest three scheduled health executions observed by this audit succeeded. An earlier failure documented in the production incident remains historical evidence, not a claim that every current health execution fails.

The release also intentionally introduced transaction-owned connection pooling, Blob publication/job/provider receipts and recovery, chart evidence navigation, learning corrections, Admin Health and a 120-second database-role statement timeout. A blind rollback of every image would remove useful work alongside the regressions. Restoration must preserve the accepted functionality of each consumer.

## Evidence and limits

Production target/digest provenance is in the [production release receipt](../system-reliability-production-2026-10-16/release.json), with the [combined source hashes](../system-reliability-2026-10-16/release.json). Those receipts establish what was packaged; their previous source-preservation acceptance is superseded by this audit.

The audit compared the actual prior API, Trading, queued-research, general, fundamentals, health and broker image application layers, the actual released worker/API layers, and retained immutable-image source receipts for Home/equities/macro. Runtime worker Python hashes match the recorded release manifest; the subsequent API-only Health collector update accounts for its expected difference. Frontend source was compared with the accepted native-workbench build context. Files inherited unchanged by a role-specific image were not treated as deleted merely because a common worker lacked them.

The actual released broker was also reconstructed: every copied Python hash matches its role-specific release manifest, including the overwritten cadence/store functions. The prior legacy API source was retained separately rather than assuming it matched the modern API. The [current public response measurements](runtime-observation.json) contain counts and publication identity without private source text or credentials.

Image reconstruction must include application files written by RUN steps, not just COPY layers. An initial COPY-only comparison produced false differences in portfolio helpers; the complete application-layer reconstruction corrected them before this report. Private source/diff evidence, digest-verified layer projections, current Home output and read-only audit utilities are under `~/Library/Application Support/SpectralNature/release-blast-radius-20261016/`. They are evidence, not an executable application tree or a release source. Retired application trees were not restored.

No full paid Home/news/Trading regeneration, broker operation or production stress workload was started. Source compatibility and observed output establish the failures above; they do not establish the frequency of every downstream failure or certify every feature of the stack.
