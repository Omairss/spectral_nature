# Native workbook engine qualification

October23,2026. This experiment tests a distributable calculation engine for shared Zopedia file execution. It does not introduce a benchmark-local agent. No model inference, native FINCH success or production workbook feature is claimed.

The dependency-only Debian image contains LibreOffice25.2.3.2, PythonUNO and openpyxl. It packages no application or benchmark source. The trusted [probe](probe.py) receives only five declared actor files, with no evaluator files, application directory or credentials. Execution uses nonrootUID10001, no network, a read-only root, dropped capabilities, no privilege escalation and bounded memory/processes. Macros and external updates are disabled through the native load properties. [Execution output](execution.json) and the [personal review](personal-review.json) record the actual boundary and its limits. This local ARM64 container does not qualify the hosted production boundary or arbitrary generated code.

The hypothetical five-year DCF agrees with an independently calculated Python reference. BaseFCF100, growth5%, terminal growth2.5%, debt200, cash50 and shares10 give136.88550133per share at10%WACC. Saving and reopening retains the formula and result. Changing WACC to12%after reopening recalculates to104.50751857. Matching million-unit monetary inputs and share counts give per-share currency units. This is an engine calculation proof, not a company valuation or a professional finished workbook.

Five original FINCH workbooks cover statements, charts, drawings, external links and a pivot table. All original sheet names and expanded ordinary formulas survive. Most numeric changes are serialization differences around15-digit precision, with maximum measured relative differences below4.6e-15. Actual compatibility gaps remain:17pivot labels change, one blank Excel shape disappears, and two statement sheets gain merged ranges. A pivot cache also becomes an additional sheet. The engine is not accepted for blanket preservation of complex existing models.

The first inspection reader mishandled shared-formula followers and merge ordering. Read-only openpyxl expansion and canonical merge ranges removed those inspection artifacts before the personal assessment. Openpyxl never authored these workbooks. Do not treat the initial raw difference counts as financial errors or hide the remaining genuine changes.

Next work belongs in the shared analysis owner: declared input files, an isolated hosted executor, owned output storage, cancellation and typed file artifacts that both clients can download. Qualify the production Linux boundary before promotion. The original actor/evaluator stores and issued forecasts remain unchanged. Both local probe containers were removed and the VM stopped after inspection.
