# Project Philosophy

Compact operating rules distilled from [learnings.md](./learnings.md) and [mistakes.md](./mistakes.md). Source links point to the active notes.

Core Principles.
**DO NOT** Overfixate on deterministic code.
**DO NOT** attempt to create a durable artifact quickly.
**DO NOT** write helper code and bandaid fixes. No hedging.
**DO NOT** prioritize getting a working artifact over the quality.
**DO NOT** patched quality failures locally. Deep fix.
**DO NOT** Try to close the task superficially. If it doesn't work. You can return and tell me the state and we will try another approach.
**DO** Understand the spirit of the question and implement it deeply. **NO LAZINESS**
Forget about test and forget about passing tests for anything based on LLM qualitative assesments. YOu will personally evaluate how good this is. DO NOT treat LLM development as traditional software engineering


- **One spine, thin surfaces.** Shared research/data behavior belongs in AQL/Zopedia/data contracts; Streamlit, API, jobs, and adapters render or trigger it. No sidecar agents or shortcut LLM paths. Business-memory verdicts must be produced through the shared AQL/Zopedia agent, not feature-local LLM calls. Refs: [L17](./learnings.md#L17), [L184](./learnings.md#L184), [L197](./learnings.md#L197), [M59](./mistakes.md#L59), [M132](./mistakes.md#L132), [M144](./mistakes.md#L144).
- **Fix upstream.** Wrong output means inspect the data, service, contract, or materialized artifact first. Product state must be durable, typed, and traceable; UI copy is not a data model. Refs: [L18](./learnings.md#L18), [L19](./learnings.md#L19), [M36](./mistakes.md#L36), [M75](./mistakes.md#L75).
- **No needless complexity, no band aids.** Prefer the simplest durable source fix that respects the core architecture. Do not add side helpers, ornate orchestration, new abstractions, or UI/prose patches to cover a broken contract. If the real fix is larger, name it and do it deliberately. Refs: [L145](./learnings.md#L145), [L181](./learnings.md#L181), [M105](./mistakes.md#L105), [M129](./mistakes.md#L129).
- **Ground before writing.** Preserve rich text, chunks, source refs, and coverage checks before synthesis. Read memory/source refs before citing them; when previews are shallow, open the source through the shared Zopedia/AQL acquisition path and escalate crawling there. Premium investor commentary such as Seeking Alpha belongs in that same plan/acquisition/quality contract as research direction, not as a side helper or final authority. Cap confidence or fail closed when evidence is thin. Refs: [L44](./learnings.md#L44), [L148](./learnings.md#L148), [L154](./learnings.md#L154), [L190](./learnings.md#L190), [L209](./learnings.md#L209), [M37](./mistakes.md#L37), [M118](./mistakes.md#L118), [M138](./mistakes.md#L138), [M157](./mistakes.md#L157).
- **Freshness is evidence, not decoration.** Preserve or infer publish dates before synthesis. Old dated material can inform background context, but only same-day/recent evidence may drive why-today fields, supported-cause labels, or Home attention titles. Undated search snippets are not proof of a current trigger. Refs: [L216](./learnings.md#L216), [M163](./mistakes.md#L163).
- **Driver precision must match the evidence.** Broad rally evidence supports a broad rally story. Do not name a precise macro, geopolitical, policy, customer, or financing cause unless recent evidence directly ties that force to the ticker, peer group, sector, or market move. Refs: [L227](./learnings.md#L227), [M173](./mistakes.md#L173).
- **Freshness applies to all current-feed artifacts.** A stale row is still product risk if it is hidden from the main title but persisted into search-news tables, ticker background snapshots, or page-summary context. Apply the evidence-age contract at every materialized current-feed boundary. Refs: [L222](./learnings.md#L222), [M169](./mistakes.md#L169).
- **Research before judgment.** AQL/Zopedia should first acquire and preserve candidate sources, then run a structured synthesis over those exact sources before writing stories or wiki facts. Do not let a later judgment step ignore already-found evidence and restart as if the source set were empty. Refs: [L196](./learnings.md#L196), [L207](./learnings.md#L207), [M155](./mistakes.md#L155).
- **Use LLMs for narrative and planning; use code for contracts.** Do not hardcode user-facing prose, market intent classifiers, or query-specific branches. Code may assemble IDs, counts, source traces, empty shells, and routing metadata; it must not synthesize claims, causes, market stories, or verification verdicts. If the LLM/Zopedia path is missing or fails, fail closed with empty narrative and exact status. Refs: [L65](./learnings.md#L65), [L147](./learnings.md#L147), [L198](./learnings.md#L198), [M44](./mistakes.md#L44), [M109](./mistakes.md#L109), [M146](./mistakes.md#L146).
- **Materialization is not research.** Snapshot builders and persistence layers should batch local frames, source traces, and structured rows. They must not hide live web calls, taxonomy DB lookups, or per-symbol LLM synthesis after the agent has already run. Live interpretation belongs at the shared Zopedia/AQL boundary; materialization should be fast and auditable. Refs: [L214](./learnings.md#L214), [M161](./mistakes.md#L161).
- **LLM quality is judged by live output, not fixed tests.** For qualitative LLM features, deterministic tests can protect plumbing, schemas, and fail-closed state, but they do not prove quality. The responsible check is to run the live path, read the produced story/facts/gaps, and personally judge whether it satisfies the user’s intent. Do not contort LLM behavior to satisfy fixed string tests.
- **Agents need coverage, not theater.** More tools or choreography do not fix weak retrieval. Plan evidence slots, preserve the user's wording, seed required context, and use internal evidence before live search when appropriate. Refs: [L53](./learnings.md#L53), [L55](./learnings.md#L55), [L186](./learnings.md#L186), [M98](./mistakes.md#L98), [M110](./mistakes.md#L110).
- **Long agent jobs need a visible research journal.** Background Zopedia/AQL work should not look silent. Emit high-level plan, tool intent, evidence result previews, redirects, source gaps, and completion status as durable progress logs. Do not expose raw hidden chain-of-thought; log concise rationale and observable evidence movement.
- **A general agent gets harness discipline, not feature handcuffs.** If Zopedia/AQL wanders, improve the shared prompt, context contract, traversal rules, and trajectory monitor. Do not hide the problem by narrowing tools in one feature path or bypassing the general agent with a private planner. Refs: [L200](./learnings.md#L200), [L203](./learnings.md#L203), [M148](./mistakes.md#L148), [M150](./mistakes.md#L150).
- **Repair planner mechanics at the harness boundary.** Tool schemas, argument coercion, empty tool names, and restart instructions belong in the shared Zopedia/AQL harness. These repairs preserve the general agent and protect research budget; they must not become feature-specific narrative shortcuts. Refs: [L229](./learnings.md#L229), [M175](./mistakes.md#L175).
- **Weak seeds are normal.** A ticker, partial name, sparse baseline, or noisy company label is a valid starting point. The shared Zopedia/AQL agent should recover enough business identity and context during research. Do not add a separate name-cleanup gate or optimize away useful tool use just because the first seed was thin. Refs: [L187](./learnings.md#L187), [L206](./learnings.md#L206), [M142](./mistakes.md#L142), [M154](./mistakes.md#L154).
- **Recovered identity becomes product state.** If Zopedia/AQL resolves a weak ticker seed during planning or synthesis, write the recovered company name back to the stack/proposal row. Do not leave the artifact labeled unresolved while the story uses the right name. Refs: [L208](./learnings.md#L208), [M156](./mistakes.md#L156).
- **Optimize for organized recall, not narrow recall.** For company research, adjacent context is often the point: first-degree and second-degree neighbor tickers, parent/platform, peers, customers, suppliers, sector demand, rates, credit cycle, policy, market spillovers, private-company leaders, and IPO speculation can all explain the business. Attention-event research should widen from exact tickers to plausible sector/macro/private-company drivers before calling a move unexplained. The failure is not recalling related things; the failure is failing to organize them around the primary company or event, keep the work inside the job boundary, and explain why the neighbor matters. Refs: [L204](./learnings.md#L204), [L213](./learnings.md#L213).
- **New evidence resolves against memory.** News, filings, transcripts, and source uploads should become source-backed events that Zopedia compares against durable company/theme memory before writing a story. The answer is what changed, what was confirmed, what conflicts, and what memory update is proposed. Ref: [L168](./learnings.md#L168).
- **Trading research is business-first.** For company candidates, the agent studies the underlying business first: products, customers, demand, bookings/revenue quality, workforce, hiring, employee sentiment, web attention, global trends, and policy support. Price, technicals, and anomalies explain where to look; they are not the core thesis. Ref: [L167](./learnings.md#L167).
- **Evidence is not analysis.** Do not surface "evidence exists" as an answer. Business outputs must translate evidence into a verdict: strong, weak, mixed, improving, deteriorating, confirmed, contradicted, or unknown because a named slot is missing. Refs: [L180](./learnings.md#L180), [L182](./learnings.md#L182), [M128](./mistakes.md#L128), [M130](./mistakes.md#L130).
- **Resolve triggers, do not brand them.** The system should work hard to identify the business development, event, customer signal, filing detail, macro force, or missing source behind a move. User-facing copy should not keep repeating "catalyst" as a heading or filler word; it should say what changed or name the exact evidence gap. Unresolved trigger state is product state, not prose: clear the raw why field or attach Zopedia business context before rendering. Refs: [L199](./learnings.md#L199), [L211](./learnings.md#L211), [M147](./mistakes.md#L147), [M159](./mistakes.md#L159).
- **Compose broad summaries from bounded research.** For Home, Market Explorer, and economy surfaces, run focused Zopedia/AQL research for the companies/events first, then synthesize across those completed answers. Do not ask one broad agent thread to rediscover every sector, macro, and ticker cause from scratch. Refs: [L230](./learnings.md#L230), [M176](./mistakes.md#L176).
- **Absence is structured state, not copy.** "No clear catalyst", "no clear driver", and pure ticker/percent move recaps are not analysis. If Zopedia/AQL cannot produce substantive business, sector, macro, peer, or source-backed text, the card should show a concrete watch-next gap or not render that narrative. If only part of a cluster is supported, publish the supported driver and move the remaining evidence need to watch-next. Refs: [L223](./learnings.md#L223), [L224](./learnings.md#L224), [L239](./learnings.md#L239), [M170](./mistakes.md#L170), [M171](./mistakes.md#L171).
- **Guardrails must change contracts, not blacklist symptoms.** Do not prevent bad product output with phrase bans or cosmetic tests. Remove the unsafe path, strengthen the schema/state machine, or fail closed until the proper verdict layer runs. Refs: [L183](./learnings.md#L183), [M131](./mistakes.md#L131).
- **Quality monitors judge meaning, not strings.** For LLM narratives, a Zopedia/AQL critic may review a draft against the evidence contract sentence by sentence, request revision, and fail closed if the final answer still overstates evidence or turns gaps into body prose. Do not use phrase scans as the product fix. Refs: [L232](./learnings.md#L232), [L234](./learnings.md#L234), [M178](./mistakes.md#L178), [M180](./mistakes.md#L180).
- **No hedging, no filler walls.** Answers should be thesis-first, concise, and decisive when evidence supports a call. If evidence is thin, state the exact missing evidence or unresolved slot; do not pad with generic caveats, verbose process text, or stitched-together source dumps. Refs: [L157](./learnings.md#L157), [L180](./learnings.md#L180), [M127](./mistakes.md#L127), [M128](./mistakes.md#L128).
- **Product screens hide plumbing and filler.** Users see actions, answers, evidence, progress, and clear unavailable states. Admin/job/materialized/runtime language and operational controls belong behind a debug toggle, in Admin, docs, or logs. Every rendered word must help the user make a decision; do not add generic marketing, trust, access, or workspace captions to fill space. Critique summaries, raw source names, verbose "no data" text, failed-synthesis scaffolding, failed-agent evidence packs, and low-confidence labels are internal signals, not user content. Refs: [L72](./learnings.md#L72), [L137](./learnings.md#L137), [L157](./learnings.md#L157), [L215](./learnings.md#L215), [M51](./mistakes.md#L51), [M95](./mistakes.md#L95), [M103](./mistakes.md#L103), [M160](./mistakes.md#L160), [M162](./mistakes.md#L162).
- **Keep render paths cheap and read-only; give background jobs real research budgets.** Show existing state first in UI. Heavy AQL/LLM/media work runs in scheduled jobs or explicit actions with explicit budgets at the shared engine boundary; page render must not start hidden media generation, live AQL research, or provider work. A bad or missing materialized Home snapshot must fail closed, not launch agent research from Streamlit. Primary feed artifacts should not wait behind optional independent enrichment. Do not force background research through urgent chat timeouts. Keep overall parallelism high for independent endpoints, but throttle repeated calls per provider and hostname. Refs: [L101](./learnings.md#L101), [L106](./learnings.md#L106), [L197](./learnings.md#L197), [L210](./learnings.md#L210), [L218](./learnings.md#L218), [L219](./learnings.md#L219), [L240](./learnings.md#L240), [M82](./mistakes.md#L82), [M94](./mistakes.md#L94), [M145](./mistakes.md#L145), [M158](./mistakes.md#L158), [M165](./mistakes.md#L165), [M166](./mistakes.md#L166), [M185](./mistakes.md#L185), [M186](./mistakes.md#L186).
- **Home is group-first.** The attention homepage should keep research and ticker detail nested inside the relevant narrative group. Do not revive a detached right-side detail rail, and do not assemble drilldown content at click time; reveal the bundle/background/enrichment rows already materialized by the job.
- **Acquisition stages need visible bounded fan-out.** Shared search/news/crawler acquisition should run with small provider-safe parallelism, per-item timeouts, and progress logs. A single slow ticker or endpoint must not make the homepage look hung. Refs: [L231](./learnings.md#L231), [M177](./mistakes.md#L177).
- **Caches follow artifact identity.** Materialized AQL/Zopedia output may be cached for UI speed, but the cache key must include dataset version, run id, or as-of time. A user session should not preserve stale agent text after a new snapshot is published. Refs: [L226](./learnings.md#L226), [M172](./mistakes.md#L172).
- **Public materialized rows are not trace dumps.** UI-facing summaries store the clean display contract only. Tool calls, evidence packs, monitor decisions, review-note prose, and failed-agent details stay in AQL/Zopedia debug artifacts or admin views. Every UI-facing field and bundle copy must be owned by the final semantic surface review. Refs: [L228](./learnings.md#L228), [L236](./learnings.md#L236), [L237](./learnings.md#L237), [M162](./mistakes.md#L162), [M182](./mistakes.md#L182), [M183](./mistakes.md#L183).
- **Make durable changes auditable and reversible.** Chat, memory writes, social state, generated assets, and learning updates need stable anchors, source refs, audit rows, promotion states, executable rollback, and hardened persistence schemas where relevant. A completed research run should not be lost to a mixed provider column at write time, and optional tracking infrastructure must never block product work. Refs: [L159](./learnings.md#L159), [L160](./learnings.md#L160), [L171](./learnings.md#L171), [L196](./learnings.md#L196), [L220](./learnings.md#L220), [L221](./learnings.md#L221), [M119](./mistakes.md#L119), [M167](./mistakes.md#L167), [M168](./mistakes.md#L168).
- **Page rewrites audit the old renderer.** When building vN+1 of a page, diff every feature in the vN renderer: audio players, share buttons, debug traces, replay controls. Explicitly include or consciously drop each one. A dropped feature the user relied on is a regression, not a simplification. Refs: [L156](./learnings.md#L156), [M50](./mistakes.md#L50).
- **Verify the live user path.** Test the smallest callable unit, then the exact screen, API, job, deployed env, and runtime identity as applicable. Code exists does not mean the feature is live. Refs: [L37](./learnings.md#L37), [L165](./learnings.md#L165), [L176](./learnings.md#L176), [M18](./mistakes.md#L18), [M142](./mistakes.md#L142).
- **Iterate with targeted probes before full jobs.** Prefer small callable units, synthetic frames, latest materialized-frame replays, render-preview text extraction, and focused LLM calls for development. Run the full scheduled job only after the local contract and qualitative output already look right. Ref: [L212](./learnings.md#L212).
- **Security and deployment fail closed.** Secrets live in Key Vault, auth/session restore re-checks current status, dev deploys use repo scripts, and prod waits for explicit permission. Runtime env and identity are part of the release. Refs: [L31](./learnings.md#L31), [L155](./learnings.md#L155), [M14](./mistakes.md#L14), [M30](./mistakes.md#L30), [M163](./mistakes.md#L163).
