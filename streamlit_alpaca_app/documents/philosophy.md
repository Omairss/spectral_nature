# Project Philosophy

Compact operating rules distilled from [learnings.md](./learnings.md) and [mistakes.md](./mistakes.md). Source links point to the active notes.

Core Principles.
**Choose study compute by total cost.** Before model studies and analysis batches, estimate Lambda GPU execution versus DeepSeek API execution and use the cheaper suitable option. Preserve required model quality, context and capabilities; include measured throughput, batching, reasoning tokens, cache discounts, startup/model loading, idle time, storage and verified shutdown. Record the comparison with each study and revisit it as workload or prices change. This is the owner's October23 standing instruction.
**The web product is Next.js.** Streamlit and the earlier Dash prototype are retired, including their launch/deployment tools and UI-only dependencies. Historical directory/resource names do not define current architecture. Read the active architecture map and release record before selecting consumers. Retired code stays archived outside the checkout for 30 days; never restore it as a compatibility path.
**Keep the repository tidy.** Cleanup may precede a task when justified. Archive superseded material first, retain it for 30 days, then automatically discard expired archives during routine cleanup. Keep canonical plans and current indices clear.
**One authority for release source.** Reconcile accepted application changes in Git and build all consumers from the identified accepted revision. Historical images, temporary overlays, extracted source copies and archives cannot seed a new application release. A hash check proves copying, not preservation of newer behavior. See the [release-source policy](infra/RELEASE_SOURCE_POLICY.md) and [October 16 retirement record](verification/release-source-retirement-2026-10-16/README.md).
**Acceptance covers the whole application.** Packaging must pass the committed source acceptance record: complete runtime inventory, review of every changed file, component evidence and each consumer's prior accepted image. This includes Home, data producers, provider wrappers, broker scheduling and monitoring outside the research-engine fingerprint. Inherited images provide dependencies only; replace their entire application tree.
**Cheap open-source models are non-negotiable.** Improve the complete prediction system around them: harness, research loops, information retrieval, relevance/ranking, projections, forecasting, strategy, bet sizing and optionality. Mark cheaper eligible models with better evidence separately; hold the model fixed when measuring system improvements. Apply the model constraint to offline teachers and graders too. See the [prediction-machine scope](research/frontier-agentic-research/PREDICTION_MACHINE_SCOPE_2026-10-16.md).
**DO NOT** Overfixate on deterministic code.
**DO NOT** attempt to create a durable artifact quickly.
**DO NOT** write helper code and bandaid fixes. No hedging.
**DO NOT** prioritize getting a working artifact over the quality.
**DO NOT** patched quality failures locally. Deep fix.
**DO NOT** Try to close the task superficially. If it doesn't work. You can return and tell me the state and we will try another approach.
**DO** Understand the spirit of the question and implement it deeply. **NO LAZINESS**
Evaluate LLM behavior with frozen comparative evals and personal review of complete outputs. Passing software tests or matching expected prose does not establish reasoning quality. Use held-out cases and preserve useful alternative answers; do not tune only to familiar examples.


- **One spine, thin surfaces.** Shared research/data behavior belongs in AQL/Zopedia/data contracts; Next.js, native iOS, API, jobs, and adapters render or trigger it. No sidecar agents or shortcut LLM paths. Business-memory verdicts must be produced through the shared AQL/Zopedia agent, not feature-local LLM calls. A tagged loader is not enough: research-grade model calls need an enforceable AQL/Zopedia gateway that records surface, purpose, provider, model, status, and artifact links. Refs: [L17](./learnings.md#L17), [L184](./learnings.md#L184), [L197](./learnings.md#L197), [L307](./learnings.md#L307), [M59](./mistakes.md#L59), [M132](./mistakes.md#L132), [M144](./mistakes.md#L144), [M78](./mistakes.md#L78). A common provider gateway alone does not consolidate research. The shared engine owns planning, acquisition, synthesis, review, budgets, continuation and public progress; feature adapters define tasks and format results. Release the same engine revision to every dev consumer, including queued workers.
- **The product frontend is a chat-first research workbench.** Conversation is the only authoring and control surface. The agent creates market views, datasets, notebooks, code, reports, Zopedia knowledge, graphs, and runs as linked typed artifacts; users inspect the code, diffs, provenance, logs, and outputs but request changes through chat rather than editing or executing code. Keep agent context explicit and code/ML execution isolated from browser and application hosts. Refs: [L390](./learnings.md#L390), [L391](./learnings.md#L391).
- **Conversations outlive execution attempts.** Keep conversation, message and run identity distinct. A failed turn must retain earlier research, user corrections and its recorded execution outcome. Publish concise research actions, sources, findings and next steps through a shared progress contract; private model reasoning and raw diagnostics remain separate. See the [October 14 conversation audit](./architecture/AQL/audits/ZOPEDIA_CONVERSATION_AUDIT_2026-10-14.md).
- **Research is an LLM discovery and recommendation platform.** Optimize useful connections, organized recall, exploration, and continuing research. Sparse tickers and indirect articles are valid leads; identity hints help the agent infer and correct, rather than requiring exact issuer details in each source. Reasonable research errors are tolerable and should improve memory through correction. Historical observations and article-derived Zopedia knowledge can independently nominate subjects before daily selection. Detecting change, explaining it, and predicting future outcomes are separate objectives.
- **Remain useful under imperfect evidence.** Assess which conclusions depend on a disputed detail and preserve independent findings. A recoverable call or source error must not erase completed research or automatically invalidate the whole analysis. Let the shared learner judge corrections from complete episodes; reuse sound lessons and retain failed learning attempts for retry without turning examples into fixed rules.
- **Maximize expected relevance with high recall.** Noisy leads, indirect connections and reasonable hypotheses are useful research output. LLMs organize and rank them; review improves the explanation and directs follow-up. Do not turn reviewer verdicts, source counts, exact citations, phrase checks or proven causality into publication admission rules. Code enforces execution, schemas and permissions. Durable knowledge writes retain their separate authorization and audit policy.
- **Learning architecture needs explicit objectives.** Specify observations, representations, fitting objectives, cold-start behavior and evaluation before claiming a redesign is grounded in ML. Financial narratives suggest hypotheses, not laws. User examples diagnose general failures; never turn their tickers, sectors or described paths into coded rules or model classes. Learn relationships and research relevance from data; returns and risk direct research selection, while statistical prediction and research usefulness receive separate review. See the [October 7 technical redesign, revision 2](../output/pdf/SPECTRAL_NATURE_LLM_DISCOVERY_REDESIGN_2026-10-07.pdf).
- **Events can initiate and organize research.** A source event, private entity or concept can become a shared investigation before any public ticker passes a mover filter. Let AQL/Zopedia discover the connections, plan focused follow-ups and synthesize their context into the main story. Ingested headlines are valid leads; limited article access and uncertain mappings guide follow-up rather than erase the event. Numerical learners and article-derived knowledge contribute independently. See the [October 8 architecture correction (archived)](verification/legacy-retirement-2026-10-16/README.md).
- **Visualizations are validated artifacts, not executable model output.** The sandbox emits typed datasets and allowlisted renderer specifications with provenance. Specialized renderers may share one interaction and design contract, but arbitrary generated JavaScript, HTML, shaders, packages, and remote data URLs do not run in the product origin. Ref: [L392](./learnings.md#L392).
- **Providers are replaceable inference transports.** DeepSeek and future local GPU runtimes implement the same small JSON model contract. Research sessions, event history, tool discovery, evidence, Zopedia memory, and product artifacts remain application-owned; do not introduce a hosted agent SDK or provider-managed session dependency into the shared spine. Refs: [L324](./learnings.md#L324), [L325](./learnings.md#L325), [M229](./mistakes.md#L229).
- **Fix upstream.** Wrong output means inspect the data, service, contract, or materialized artifact first. Product state must be durable, typed, and traceable; UI copy is not a data model. Refs: [L18](./learnings.md#L18), [L19](./learnings.md#L19), [M36](./mistakes.md#L36), [M75](./mistakes.md#L75).
- **No needless complexity, no band aids.** Prefer the simplest durable source fix that respects the core architecture. Do not add side helpers, ornate orchestration, new abstractions, or UI/prose patches to cover a broken contract. If the real fix is larger, name it and do it deliberately. Refs: [L145](./learnings.md#L145), [L181](./learnings.md#L181), [M105](./mistakes.md#L105), [M129](./mistakes.md#L129).
- **Ground before writing.** Preserve rich text, chunks, and available source references. Read memory and sources before citing them; acquire full text through shared Zopedia/AQL when previews are shallow. Broad and indirect commentary can guide research even without exact ticker attribution. Thin evidence guides follow-up and how a connection is expressed; it does not automatically exclude a worthwhile lead or require complete provenance. Premium commentary belongs in the same acquisition path as research direction, not final authority. Refs: [L44](./learnings.md#L44), [L148](./learnings.md#L148), [L154](./learnings.md#L154), [L190](./learnings.md#L190), [L209](./learnings.md#L209), [M37](./mistakes.md#L37), [M118](./mistakes.md#L118), [M138](./mistakes.md#L138), [M157](./mistakes.md#L157).
- **Freshness is evidence, not decoration.** Preserve or infer observation and publication dates. Older knowledge can explain ongoing developments and support new research; an ongoing Home subject does not need an invented same-day cause. Claims about a new trigger must match the actual timing of the evidence. Keep numerical observations current independently of narrative availability. Refs: [L216](./learnings.md#L216), [M163](./mistakes.md#L163).
- **Driver precision must match the claim.** Distinguish an observed change, a plausible connection worth investigating, and a supported explanation. Indirect sector or macro evidence can nominate research without naming every company. Let the LLM organize the connection and competing explanations; do not require exact source matching as a universal admission rule. Do not present historical association or a financial narrative as established causality. Refs: [L227](./learnings.md#L227), [M173](./mistakes.md#L173).
- **Model context is an owned representation.** Keep instructions separate from typed evidence and durable traces. Share identical source content by reference; do not drop leads or text to hide duplicated context. Hierarchical summaries are optional navigable views over retained originals; the agent can move across levels, retrieve originals and follow indirect connections without a fixed depth or mandatory summarization sequence. Measure actual planning, retrieval, synthesis and review inputs; inspect complete model output before release.
- **Pay for incremental useful research.** Reuse versioned completed artifacts and stable evidence prefixes; downstream consumers must actually receive those findings. Let the LLM choose what new evidence is worth acquiring. Preserve research breadth, uncertain connections and full passages. Provider accounting includes actual attempts, failed work, recovery and explicit unknowns; distinguish stage savings from complete-workload savings. Private inputs require declared ownership before shared reuse. Reduced reasoning and consolidated reviews need personal comparison of complete live outputs.
- **Preserve dates throughout the research context.** Carry observation and publication dates into search-news tables, ticker background snapshots and page summaries. Older reports can remain useful for ongoing developments and established context; let the LLM assess their relevance. Do not erase useful research through a universal age cutoff or present an old observation as a new event. Refs: [L222](./learnings.md#L222), [M169](./mistakes.md#L169).
- **Research before judgment.** AQL/Zopedia should first acquire and preserve candidate sources, then run a structured synthesis over those exact sources before writing stories or wiki facts. Do not let a later judgment step ignore already-found evidence and restart as if the source set were empty. A transient planner failure after evidence collection ends planning and hands that evidence to synthesis; it does not erase the run. Refs: [L196](./learnings.md#L196), [L207](./learnings.md#L207), [L343](./learnings.md#L343), [M155](./mistakes.md#L155), [M34](./mistakes.md#L34).
- **Use LLMs for narrative and planning; use code for contracts.** Do not hardcode user-facing prose, market intent classifiers, or query-specific branches. Code may assemble IDs, counts, source traces, empty shells, and routing metadata; it must not synthesize claims, causes, market stories, or verification verdicts. If no usable LLM artifact exists, retain the last available artifact and record the execution failure rather than inventing narrative. An incomplete or unsuccessful review does not discard a valid research answer. Refs: [L65](./learnings.md#L65), [L147](./learnings.md#L147), [L198](./learnings.md#L198), [M44](./mistakes.md#L44), [M109](./mistakes.md#L109), [M146](./mistakes.md#L146).
- **Materialization is not research.** Snapshot builders and persistence layers should batch local frames, source traces, and structured rows. They must not hide live web calls, taxonomy DB lookups, or per-symbol LLM synthesis after the agent has already run. Live interpretation belongs at the shared Zopedia/AQL boundary; materialization should be fast and auditable. Refs: [L214](./learnings.md#L214), [M161](./mistakes.md#L161).
- **Evaluate LLM quality through controlled replay and personal review.** Frozen questions, evidence, memory and tool data support paired baseline/candidate evals through the shared engine, with held-out cases and repeated runs where variability matters. Changed prompts/models require fresh inference, but not current web access, production jobs or deployment. Grade reasoning, usefulness, unnecessary review edits, completion, latency and complete-workflow cost; use independent assessment and personally inspect full outputs. Deterministic checks protect contracts and verify objective calculations, not expected prose or a single approved narrative. Use small live integration checks after replay acceptance. Historical market replay needs available-at-time inputs and separate outcome labels; frozen tools do not remove a model's possible knowledge of later events.
- **Agents need coverage, not theater.** More tools or choreography do not fix weak retrieval. Plan evidence slots, preserve the user's wording, seed required context, and use internal evidence before live search when appropriate. Refs: [L53](./learnings.md#L53), [L55](./learnings.md#L55), [L186](./learnings.md#L186), [M98](./mistakes.md#L98), [M110](./mistakes.md#L110).
- **Long agent jobs need a visible research journal.** Background Zopedia/AQL work should not look silent. Emit high-level plan, tool intent, evidence result previews, redirects, source gaps, and completion status as durable progress logs. Do not expose raw hidden chain-of-thought; log concise rationale and observable evidence movement.
- **A general agent gets harness discipline, not feature handcuffs.** If Zopedia/AQL wanders, improve the shared prompt, context contract, traversal rules, and trajectory monitor. Do not hide the problem by narrowing tools in one feature path or bypassing the general agent with a private planner. Refs: [L200](./learnings.md#L200), [L203](./learnings.md#L203), [M148](./mistakes.md#L148), [M150](./mistakes.md#L150).
- **Repair planner mechanics at the harness boundary.** Tool schemas, argument coercion, empty tool names, and restart instructions belong in the shared Zopedia/AQL harness. These repairs preserve the general agent and protect research budget; they must not become feature-specific narrative shortcuts. Refs: [L229](./learnings.md#L229), [M175](./mistakes.md#L175).
- **Weak seeds are normal.** A ticker, partial name, sparse baseline, or noisy company label is a valid starting point. The shared Zopedia/AQL agent should recover enough business identity and context during research. Do not add a separate name-cleanup gate or optimize away useful tool use just because the first seed was thin. Refs: [L187](./learnings.md#L187), [L206](./learnings.md#L206), [M142](./mistakes.md#L142), [M154](./mistakes.md#L154).
- **Recovered identity becomes product state.** If Zopedia/AQL resolves a weak ticker seed during planning or synthesis, write the recovered company name back to the stack/proposal row. Do not leave the artifact labeled unresolved while the story uses the right name. Refs: [L208](./learnings.md#L208), [M156](./mistakes.md#L156).
- **Optimize for organized recall, not narrow recall.** For company research, adjacent context is often the point: first-degree and second-degree neighbor tickers, parent/platform, peers, customers, suppliers, sector demand, rates, credit cycle, policy, market spillovers, private-company leaders, and IPO speculation can all explain the business. Attention-event research should widen from exact tickers to plausible sector/macro/private-company drivers before calling a move unexplained. The failure is not recalling related things; the failure is failing to organize them around the primary company or event, keep the work inside the job boundary, and explain why the neighbor matters. Refs: [L204](./learnings.md#L204), [L213](./learnings.md#L213).
- **New evidence resolves against memory.** News, filings, transcripts, and source uploads should become source-backed events that Zopedia compares against durable company/theme memory before writing a story. The answer is what changed, what was confirmed, what conflicts, and what memory update is proposed. Ref: [L168](./learnings.md#L168).
- **Trading research is business-first.** For company candidates, the agent studies the underlying business first: products, customers, demand, bookings/revenue quality, workforce, hiring, employee sentiment, web attention, global trends, and policy support. Price, technicals, and anomalies explain where to look; they are not the core thesis. Ref: [L167](./learnings.md#L167).
- **Direction, confidence and approval are distinct.** The owner requests a preferred long/short call for each successfully analyzed Trading selection, even when uncertain. Failed execution remains a failure. A direction enum or invented scenario numbers do not establish sound reasoning; inspect the economics and opposing case. Paper approval freezes the thesis and tracking convention; broker execution requires its separate confirmation. See the [October 16 implementation and quality hold](plans/TRADING_CALLS_AND_APPROVAL_TRACKING_2026-10-16.md).
- **Accept a framework for measurable iteration, not perfect predictions.** The owner clarified that Trading needs a strong, general framework that can improve through use. Preserve original decisions and assumptions, measure dated outcomes honestly, isolate failures and make corrections reproducible. Remaining model errors are evidence for the next iteration, not an automatic veto on a useful paper-research pilot. Distinguish recording/review capability from demonstrated improvement; do not claim that outcomes automatically teach the agent unless that connection exists and is evaluated. Normal integration, ownership and release checks still apply.
- **Keep the workspace tidy.** Clean up and reorganize as work proceeds. Archive retired material before removal, with automatic discard after 30 days; keep active source, current documentation and needed research evidence organized and distinguish them from disposable build output.
- **Evidence is not analysis.** Do not surface "evidence exists" as an answer. Business outputs explain the practical meaning, plausible connections and useful follow-up. Do not force every analysis into a fixed verdict vocabulary. Refs: [L180](./learnings.md#L180), [L182](./learnings.md#L182), [M128](./mistakes.md#L128), [M130](./mistakes.md#L130).
- **Resolve triggers, do not brand them.** The system should work hard to identify the business development, event, customer signal, filing detail, macro force, or missing source behind a move. User-facing copy should not keep repeating "catalyst" as a heading or filler word; it should say what changed or name the exact evidence gap. An unresolved cause can still support useful business context and a hypothesis. Let the shared editor express that connection; the read path must not clear it with phrase checks. Refs: [L199](./learnings.md#L199), [L211](./learnings.md#L211), [M147](./mistakes.md#L147), [M159](./mistakes.md#L159).
- **Compose broad summaries from bounded research.** For Home, Market Explorer, and economy surfaces, run focused Zopedia/AQL research for the companies/events first, then synthesize across those completed answers. Do not ask one broad agent thread to rediscover every sector, macro, and ticker cause from scratch. Refs: [L230](./learnings.md#L230), [M176](./mistakes.md#L176).
- **Absence is structured state, not copy.** "No clear catalyst", "no clear driver", and pure ticker/percent move recaps are not analysis. Ask the shared editor for substantive business, sector, macro or peer connections and concrete follow-up. Partial support can improve the explanation without excluding the wider useful hypothesis. These are editorial objectives, not coded admission rules. Refs: [L223](./learnings.md#L223), [L224](./learnings.md#L224), [L239](./learnings.md#L239), [M170](./mistakes.md#L170), [M171](./mistakes.md#L171).
- **Guardrails must change contracts, not blacklist symptoms.** Do not fix bad output with phrase bans, ticker exceptions, or cosmetic tests. Improve the shared context, model instructions, and persistence contract. Reserve fail-closed behavior for failed execution or broken contracts when no valid artifact exists. Review can correct an unsupported claim while preserving useful research; incomplete research alone is not a reason to suppress discovery. Refs: [L183](./learnings.md#L183), [M131](./mistakes.md#L131).
- **Quality monitors judge meaning, not strings.** A shared AQL/Zopedia critic reviews usefulness, coherent connections, source relevance, and overstatement. It can request more research or revise a claim while preserving a worthwhile lead. Judge the output personally; do not optimize fixed phrase checks, exact ticker matches, or 100% provenance. Provider or review failures must not block independent numerical publication. Refs: [L232](./learnings.md#L232), [L234](./learnings.md#L234), [M178](./mistakes.md#L178), [M180](./mistakes.md#L180).
- **No hedging, no filler walls.** Answers should be thesis-first, concise, and decisive when evidence supports a call. If evidence is thin, name the useful follow-up; do not pad with generic caveats, verbose process text, or stitched-together source dumps. Refs: [L157](./learnings.md#L157), [L180](./learnings.md#L180), [M127](./mistakes.md#L127), [M128](./mistakes.md#L128).
- **Product screens hide plumbing and filler.** Users see actions, answers, evidence, progress, and clear unavailable states. Admin/job/materialized/runtime language and operational controls belong behind a debug toggle, in Admin, docs, or logs. Every rendered word must help the user make a decision; do not add generic marketing, trust, access, or workspace captions to fill space. Critique summaries, raw source names, verbose "no data" text, failed-synthesis scaffolding, failed-agent evidence packs, and low-confidence labels are internal signals, not user content. Refs: [L72](./learnings.md#L72), [L137](./learnings.md#L137), [L157](./learnings.md#L157), [L215](./learnings.md#L215), [M51](./mistakes.md#L51), [M95](./mistakes.md#L95), [M103](./mistakes.md#L103), [M160](./mistakes.md#L160), [M162](./mistakes.md#L162).
- **Keep render paths cheap and read-only; give background jobs real research budgets.** Show existing state first in UI. Heavy AQL/LLM/media work runs in scheduled jobs or explicit actions with explicit budgets at the shared engine boundary; page render must not start hidden media generation, live AQL research, or provider work. A bad or missing materialized Home snapshot must fail closed, not launch agent research during page rendering. Primary feed artifacts should not wait behind optional independent enrichment. Do not force background research through urgent chat timeouts. Keep overall parallelism high for independent endpoints, but throttle repeated calls per provider and hostname. Refs: [L101](./learnings.md#L101), [L106](./learnings.md#L106), [L197](./learnings.md#L197), [L210](./learnings.md#L210), [L218](./learnings.md#L218), [L219](./learnings.md#L219), [L240](./learnings.md#L240), [M82](./mistakes.md#L82), [M94](./mistakes.md#L94), [M145](./mistakes.md#L145), [M158](./mistakes.md#L158), [M165](./mistakes.md#L165), [M166](./mistakes.md#L166), [M185](./mistakes.md#L185), [M186](./mistakes.md#L186).
- **Broker data planes stay provider-isolated.** A high-value flaky broker such as Robinhood is a paced ingestion source with its own store, queue, cadence, health, and last-good retention; it does not enter Alpaca loaders or become a dashboard render dependency. Inventory and bound discovered catalogs before historical fan-out. Trade review and placement are the narrow live exception and must revalidate broker facts. Refs: [L396](./learnings.md#L396), [L397](./learnings.md#L397), [L398](./learnings.md#L398), [L400](./learnings.md#L400), [M20](./mistakes.md#L20), [M21](./mistakes.md#L21), [M22](./mistakes.md#L22).
- **Portfolio analytics compare like with like.** A chart becomes decision-grade when its dimensions share a defensible horizon and statistical meaning. Use local historical distributions, covariance, correlation, tail behavior, and factor structure to explain return, risk, concentration, and unusual movement; do not mix a one-day move with lifetime P/L and call the result insight. Coverage is part of every reported statistic.
- **Home is group-first.** The attention homepage should keep research and ticker detail nested inside the relevant narrative group. Do not revive a detached right-side detail rail, and do not assemble drilldown content at click time; reveal the bundle/background/enrichment rows already materialized by the job.
- **Acquisition stages need visible bounded fan-out.** Shared search/news/crawler acquisition should run with small provider-safe parallelism, per-item timeouts, and progress logs. A single slow ticker or endpoint must not make the homepage look hung. Refs: [L231](./learnings.md#L231), [M177](./mistakes.md#L177).
- **Caches follow artifact identity.** Materialized AQL/Zopedia output may be cached for UI speed, but the cache key must include dataset version, run id, or as-of time. A user session should not preserve stale agent text after a new snapshot is published. Refs: [L226](./learnings.md#L226), [M172](./mistakes.md#L172).
- **Public materialized rows are not trace dumps.** UI-facing summaries store the clean display contract only. Tool calls, evidence packs, monitor decisions, review-note prose, and failed-agent details stay in AQL/Zopedia debug artifacts or admin views. Every UI-facing field and bundle copy must be owned by the final semantic surface review. Refs: [L228](./learnings.md#L228), [L236](./learnings.md#L236), [L237](./learnings.md#L237), [M162](./mistakes.md#L162), [M182](./mistakes.md#L182), [M183](./mistakes.md#L183).
- **Make durable changes auditable and reversible.** Chat, memory writes, social state, generated assets, and learning updates need stable anchors, source refs, audit rows, promotion states, executable rollback, and hardened persistence schemas where relevant. A completed research run should not be lost to a mixed provider column at write time, and optional tracking infrastructure must never block product work. Refs: [L159](./learnings.md#L159), [L160](./learnings.md#L160), [L171](./learnings.md#L171), [L196](./learnings.md#L196), [L220](./learnings.md#L220), [L221](./learnings.md#L221), [M119](./mistakes.md#L119), [M167](./mistakes.md#L167), [M168](./mistakes.md#L168).
- **External account connections are user- and environment-owned.** An operator MCP registration is not a product integration. Hosted OAuth/MCP and direct broker-session adapters both need per-user and per-environment identity, encrypted tokens, durable audit state, and a local fail-closed capability policy. Portfolio visibility does not grant trade authority: active membership may read cached portfolio data, while connection changes, refresh, review, and execution require active admin membership rechecked inside the service and again at confirmation. Research approval, order review, and execution are separate states; no remote hint or research call may collapse them. Money movement requires an expiring, payload-bound, atomically single-use confirmation with deterministic provider identities, and generic tool paths cannot execute. Refs: [L354](./learnings.md#L354), [L355](./learnings.md#L355), [L356](./learnings.md#L356), [L357](./learnings.md#L357), [L358](./learnings.md#L358), [L371](./learnings.md#L371), [L372](./learnings.md#L372), [L373](./learnings.md#L373), [L374](./learnings.md#L374), [M6](./mistakes.md#L6), [M7](./mistakes.md#L7), [M8](./mistakes.md#L8), [M11](./mistakes.md#L11).
- **Page rewrites audit the old renderer.** When building vN+1 of a page, diff every feature in the vN renderer: audio players, share buttons, debug traces, replay controls. Explicitly include or consciously drop each one. A dropped feature the user relied on is a regression, not a simplification. Refs: [L156](./learnings.md#L156), [M50](./mistakes.md#L50).
- **Feed cards preserve useful history without repetition.** Attention uses one combined week/latest-day price chart with no period selector. Keep each fundamental's value and trend together once in a compact grid; remove the separate duplicated financial-value grid. Removing duplication does not authorize removing the charts. Before release, inspect the entire card on desktop and phone for retained features, repeated data, readable dates and overflow. See the [October 14 card correction](./plans/ATTENTION_FEED_CARD_REDESIGN_2026-10-14.md).
- **Verify the live user path.** Test the smallest callable unit, then the exact screen, API, job, deployed env, and runtime identity as applicable. Code exists does not mean the feature is live. Refs: [L37](./learnings.md#L37), [L165](./learnings.md#L165), [L176](./learnings.md#L176), [M18](./mistakes.md#L18), [M142](./mistakes.md#L142).
- **Retire the highest-risk uncertainty first.** Before building downstream behavior around an unofficial external service, run the cheapest real boundary probe: authenticate, complete provider verification, and make one read-only call.
